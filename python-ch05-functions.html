Functions & Modular Design

As programs grow, one long list of statements becomes impossible to read, test, or trust. Functions let you break a big job into small, named pieces — write each once, name it well, and call it whenever you need it.

Foundation

Why programs use functions

A function is a group of statements that performs one specific task. Instead of writing a program as a single, sprawling sequence of statements, you split it into functions — each handling one piece of the overall job. This is the divide and conquer approach, and a program built this way is called a modularized program.

Breaking a program into functions pays off in several ways:

whyThe benefits of modularizing▸
  • Simpler code. Each function is short enough to read and reason about on its own.
  • Code reuse. Write the logic once and call it as many times as you like, from anywhere in the program.
  • Better testing and debugging. You can test each function in isolation, so when something breaks you know where to look.
  • Faster development and teamwork. Different people can write different functions at the same time.

Python has two kinds of functions, distinguished by whether they hand a value back to the code that called them:

voidVoid function▸

Simply runs the statements it contains and then ends. It does something — prints a report, draws a header — but doesn't send a value back. You call it as a statement on its own line.

valueValue-returning function▸

Runs its statements and returns a value to the caller. The built-in input, int, and float functions all work this way — you use their result in an expression or assignment.

Syntax

Defining and calling a function

To create a function you write a function definition: the keyword def, a name you choose, parentheses, and a colon, followed by an indented block of statements. That first line is the function header.

header_demo.py
def show_header():
    print("============================")
    print("   Monthly Sales Report")
    print("============================")

Defining a function does not run it — it just tells Python what the function does. To actually run it, you call it by writing its name followed by parentheses:

call_demo.py
show_header()

When the call runs, the interpreter jumps to the function, executes the statements in its block, then jumps back to the line right after the call and continues. That jump back is the function return.

Naming rules

A function name should describe the task it carries out — it often contains a verb, like show_header or calculate_tax. The rules for naming functions are the same as for variables:

  • You cannot use a Python keyword (like for or def) as a name.
  • The name cannot contain spaces.
  • The first character must be a letter or an underscore.
  • Every other character must be a letter, a digit, or an underscore.
  • Uppercase and lowercase are distinct — total and Total are two different names.

The main function and indentation

Most modularized programs have a main function that runs first and calls the other functions as they're needed. It defines the program's mainline logic — the big-picture order of events:

program.py
def main():
    show_header()
    print("Report body goes here.")

# start the program by calling main
main()
Indentation is not optional

Every statement in a function's block must be indented the same amount. Use spaces consistently (don't mix tabs and spaces — it confuses the interpreter). The indentation is how Python knows which lines belong to the function. Blank lines inside a block are ignored.

Design

Designing a program to use functions

Top-down design is the technique of breaking an algorithm into functions: start with the overall task, then split it into smaller and smaller tasks until each one is simple enough to become a single function.

In a flowchart, a call to a function is drawn as a predefined-process symbol — a rectangle with a vertical bar down each side, with the function's name inside. Each function gets its own separate flowchart, and that flowchart's ending terminal usually reads Return rather than End, because control returns to the caller.

Hierarchy charts

A hierarchy chart (also called a structure chart) shows the relationships between a program's functions: a box for each function, with lines connecting a function to the ones it calls. It does not show the steps inside any function — only who calls whom.

IPO charts

An IPO chart describes a function in three columns — Input, Processing, and Output — giving a brief description of each without the detail of a flowchart. For simple functions, an IPO chart often carries enough information to design and document the function on its own.

Scope

Local variables and scope

A local variable is a variable created (assigned a value) inside a function. It belongs to that function: only statements inside the same function can use it. If code anywhere else tries to read it, an error occurs.

The scope of a variable is the part of the program where it can be accessed. For a local variable, that scope is the function in which it was created — and only from the point of its creation onward. A statement before the assignment can't use it either.

scope_demo.py
def show_message():
    greeting = "Welcome aboard"   # local to show_message
    print(greeting)

def main():
    show_message()
    print(greeting)   # ERROR: greeting doesn't exist out here

main()

The call to print(greeting) inside main fails because greeting lives only inside show_message. Once that function returns, the variable is gone.

A useful consequence

Because each function has its own private set of local variables, two different functions can both use a variable named count (or total, or i) without interfering with each other. Neither function can see the other's locals, so there's no confusion.

Inputs to functions

Passing arguments to functions

An argument is a piece of data you send into a function when you call it — placed inside the parentheses. A parameter is the variable, listed in the function header, that receives the argument's value. The parameter and the argument refer to the same value.

one_argument.py
def show_celsius(fahrenheit):
    celsius = (fahrenheit - 32) * 5 / 9
    print(fahrenheit, "F is", celsius, "C")

show_celsius(212)   # 212 is the argument; fahrenheit is the parameter

The parameter fahrenheit has the same scope as a local variable: it exists only inside show_celsius.

Passing multiple arguments

A function can accept several arguments by listing several parameters, separated by commas. Arguments are matched to parameters by position: the first argument goes to the first parameter, the second to the second, and so on.

multiple_args.py
def show_area(width, height):
    print("Area:", width * height)

show_area(8, 3)   # width = 8, height = 3  ->  Area: 24

Pass by value

When you pass an argument, the function receives a copy of the value. Changing the parameter inside the function does not change the original argument back in the caller. This is called pass by value, and it means communication flows one way — from the caller into the function.

pass_by_value.py
def reset_to_zero(number):
    number = 0
    print("Inside the function:", number)

score = 99
reset_to_zero(score)
print("Back in the caller:", score)   # still 99

Keyword arguments

A keyword argument names the parameter it's meant for, using the form parameter=value. When you name them, position no longer matters. You can mix positional and keyword arguments in one call, but every positional argument must come first.

keyword_args.py
def book_room(nights, guests):
    print(guests, "guests for", nights, "nights")

book_room(guests=2, nights=3)   # order doesn't matter with keywords
Wider scope

Global variables and global constants

A global variable is created by an assignment statement written outside of all the functions. Any statement in the file can read it, including code inside a function. But if a function needs to assign a new value to it, the function must first redeclare it with the global keyword.

global_demo.py
attempts = 0   # global variable

def record_attempt():
    global attempts        # required to reassign it
    attempts = attempts + 1
Why globals are discouraged

Global variables make programs harder to work with. Debugging is harder because many places in the code could be changing the value. Functions that rely on globals become dependent on them, which makes them hard to reuse in another program. And globals make the program as a whole harder to understand.

A global constant is different — and perfectly acceptable. It's a global name whose value is never changed. Python has no true constants, so you simulate one by creating a global variable, writing its name in ALL_CAPS by convention, and simply never reassigning it inside any function.

global_constant.py
TAX_RATE = 0.0875   # global constant — never reassigned

def total_with_tax(price):
    return price + price * TAX_RATE   # reads it, doesn't change it

Because the constant is read but never reassigned inside the function, no global declaration is needed — and using a named constant beats scattering the raw number 0.0875 throughout the program.

Outputs from functions

Writing value-returning functions

To make a function return a value, add a return statement: the keyword return followed by an expression. When the function runs that line, it stops and sends the expression's value back to the part of the program that called it.

value_returning.py
def square(number):
    result = number * number
    return result

answer = square(7)   # answer now holds 49
print(answer)

You use a returned value the same way you'd use any value: assign it to a variable, or pass it straight into another function, such as print(square(7)). Value-returning functions shine when a calculation is needed in several places, or when you want to wrap up a prompt-and-read into one reusable step.

Returning strings and Boolean values

A function can return any type of value. One that returns a string might assemble and hand back text; a Boolean function returns True or False and is perfect for testing a condition — it lets you reuse a check (and tidy up complicated input validation) by calling it instead of repeating the logic.

string_and_bool.py
def full_name(first, last):
    return first + " " + last

def is_even(number):
    return number % 2 == 0

print(full_name("Ada", "Lovelace"))   # Ada Lovelace
print(is_even(10))                  # True

Returning multiple values

A Python function can return more than one value: list the expressions after return, separated by commas. When you call such a function in an assignment, you need a matching variable on the left of the = for each value returned.

multiple_returns.py
def split_time(total_seconds):
    minutes = total_seconds // 60
    seconds = total_seconds % 60
    return minutes, seconds

m, s = split_time(200)   # m = 3, s = 20
print(m, "min", s, "sec")
A library of functions

The random module

Python's standard library is a collection of pre-written functions that ship with Python. Some are built into the interpreter (like print and input); others live in modules — files of related functions you bring in with an import statement at the top of your program.

The random module holds functions for generating random numbers — handy for games, simulations, and sampling. To call a function that lives in a module, you use dot notation: the module name, a dot, then the function name.

dice.py
import random

roll = random.randint(1, 6)   # a value-returning function
print("You rolled a", roll)

randint is itself a value-returning function: it hands back a randomly chosen integer that you can use anywhere an integer fits. The random module offers several related functions:

FunctionReturns
random.randint(1, 6)A random integer from 1 through 6 (both ends included).
random.randrange(0, 10, 2)A random integer from the sequence range would produce — here 0, 2, 4, 6, or 8.
random.random()A random float from 0.0 up to 1.0. Takes no arguments.
random.uniform(1.0, 10.0)A random float within a range you specify.
Pseudo-random, and the seed

These numbers are actually pseudo-random — produced by a formula. A seed value initializes that formula. By default Python seeds it from the system clock, so you get a fresh series each run. Calling random.seed(7) with a fixed value makes the series repeat — useful when you need reproducible results for testing.

More library functions

The math module

The math module is part of the standard library and contains functions for mathematical calculations. Each typically takes one or more values, performs an operation, and returns the result. Using it requires an import math statement.

roots.py
import math

side = math.sqrt(144)   # 12.0
print("Square root of 144 is", side)

A few of the many functions the module provides:

FunctionDescription
math.sqrt(x)Returns the square root of x.
math.ceil(x)Returns the smallest integer greater than or equal to x.
math.floor(x)Returns the largest integer less than or equal to x.
math.hypot(x, y)Returns the length of the hypotenuse from (0, 0) to (x, y).
math.log10(x)Returns the base-10 logarithm of x.

The module also defines two named values, math.pi and math.e, holding the mathematical constants π and e to high precision. Like functions, you reach them with dot notation:

circle_area.py
import math

radius = 5
area = math.pi * radius ** 2
print("Area:", area)
Organizing code

Storing functions in your own modules

You aren't limited to the standard library — you can group your own related functions into a module. Modularization means putting related functions together in a module file so a program is easier to understand, test, and maintain, and so the functions can be reused across several programs.

A module is simply a file of Python code that contains function definitions but does not call them — the programs that import it do the calling. Two rules for module names: the file name must end in .py, and it cannot match a Python keyword.

geometry.py
# geometry.py — a module of reusable functions (no calls here)
import math

def circle_area(radius):
    return math.pi * radius ** 2

def rectangle_area(width, height):
    return width * height

Another program imports the module by name and calls its functions with dot notation, exactly as it would for math or random:

main_program.py
import geometry

print(geometry.circle_area(5))
print(geometry.rectangle_area(8, 3))
The payoff

Once a function lives in a module, every program that needs it just imports the module — write the code once, reuse it everywhere. This is the same idea behind the standard library, applied to your own work.

Check yourself

Predict each answer, then open the card. Even better, try it in the console above.

Q1What's the difference between a void function and a value-returning function?▸

A void function runs its statements and ends without sending anything back. A value-returning function runs its statements and hands a value back to the caller, where you can store or use it.

Q2What is the difference between an argument and a parameter?▸

An argument is the data you pass in at the call. A parameter is the variable in the function header that receives that data. They end up referring to the same value.

Q3If a function changes its parameter, does the caller's variable change too?▸

No. Arguments are passed by value, so the function works with a copy. Reassigning the parameter has no effect on the original variable in the caller.

Q4Are global variables a bad idea? What about global constants?▸

Global variables are discouraged — they make debugging, reuse, and understanding harder. Global constants (a global name that's never reassigned, written in ALL_CAPS) are fine and often improve clarity.

Q5How do you return two values, and how do you receive them?▸

List both expressions after return, separated by a comma. At the call, use a matching variable for each value: m, s = split_time(200).

Q6What do you need before calling math.sqrt(144), and what is the dot for?▸

You need import math at the top. The dot is dot notation — it tells Python to call the sqrt function that belongs to the math module.
