True or False

10 × 1 pt = 10
  1. T / F

    A decision structure may be nested inside another decision structure.

  2. T / F

    In Python, curly braces mark the block of statements belonging to an if clause.

  3. T / F

    The expression 'Start' == 'start' evaluates to True.

  4. T / F

    If one string is a prefix of a longer string, the longer string is considered the greater of the two.

  5. T / F

    The expression temp < 18 and temp > 24 can never be True.

  6. T / F

    Anything an if-elif-else statement does could also be written using nested if-else statements.

  7. T / F

    When the left operand of an or operator is True, Python still evaluates the right operand.

  8. T / F

    A Boolean variable is of the bool data type and may reference only True or False.

  9. T / F

    If found is a Boolean variable, you must write if found == True: rather than if found:.

  10. T / F

    If a references the value 2, the expression not (a > 2) evaluates to True.

Exercise 1

Package Shipping Charges

A courier charges by weight: up to 2 kg costs $4.00; over 2 and up to 10 kg costs $8.50; over 10 and up to 25 kg costs $15.00; anything heavier costs $25.00. Write a program that reads a package weight and displays the correct charge.

  1. Read the input: weight = float(input("Package weight in kg: ")). Use 7.5 as your first test value.
  2. Write the decision as a single if-elif-else ladder that displays the charge with an f-string showing two decimal places.
  3. Run the program four more times with the weights 2.0, 10.0, 25.0, and 26.0. Record the charge for each. Explain: these are the boundary values. Why is testing them more revealing than testing 5 or 18?
  4. Explain: your ladder tests weight <= 2 first. What would happen if you moved the weight <= 25 test to the top of the ladder instead? Predict the result for a 1 kg package, then try it and record what actually happened.
  5. Add validation: before the ladder, write an if statement that displays 'Invalid weight' when weight is less than or equal to 0. Test it with -3.
  6. Explain: could the four weight brackets be written as four separate if statements instead of an if-elif-else ladder? What would go wrong?
Submit: your console transcript for steps 1–5, plus your written answers for steps 3, 4, and 6.

An amusement park ride requires a rider to be at least 13 years old and at least 120 cm tall. Write a program that reads both values and reports whether the rider may board — then explore the logical operators behind it.

  1. Read the input: age = int(input("Age: ")) and height = int(input("Height in cm: ")). Use 15 and 130.

  7. Now investigate short-circuit evaluation. Type total = 50 and count = 0, then run count != 0 and total / count > 10. Record the result. Short Answer · 2 points each

  1. The three control structures.Sequence — statements run in the exact order they appear, with no skipping or repeating. Decision (selection) — an action is performed only if a condition is true. Repetition — a set of statements repeats while some condition holds.
  2. Single vs. dual alternative.A single alternative structure offers one optional path: the block runs if the condition is true, and otherwise the program simply carries on. A dual alternative structure offers two paths and exactly one of them always runs — the if block when the condition is true, the else block when it is false.
  3. Two common syntax errors.Omitting the colon at the end of the if clause, which raises a SyntaxError; and failing to indent the block beneath it, which raises an IndentationError.
  4. = versus ==.A single = is the assignment operator: it stores a value in a variable. A double == is a relational operator: it compares two values and produces True or False. Writing if x = 4: is a syntax error in Python, which prevents a bug that is common in other languages.
  5. Boolean expression.An expression whose value is either True or False. Any relational comparison qualifies — for example players >= 4, which is True when players references 4 or more.
  6. Comparing strings; why "Banana" < "apple".Python compares character by character from left to right, using each character's numeric code, and stops at the first position where the strings differ — that single comparison decides the result. At position 0, 'B' is code 66 and 'a' is code 97. Since 66 is less than 97, "Banana" is less than "apple", even though B comes first alphabetically in ordinary usage. All uppercase letters have lower codes than all lowercase letters.
  7. How if-elif-else decides; why order matters.Python tests the conditions from the top down, runs the block belonging to the first condition that is true, and then skips the entire rest of the ladder. Because each rung has already ruled out the ranges above it, only an upper bound is needed on each test — but that only holds if the conditions appear in the right order. A broader condition placed above a narrower one will capture values meant for the narrower branch.
  8. Why prefer the ladder.Deeply nested if-else blocks march further right with each level, which makes the logic hard to follow and easy to misalign. The if-elif-else ladder keeps every clause in a single column. Accept also: fewer chances to mispair an else with the wrong if.
  9. Short-circuit evaluation.Python stops as soon as the outcome is certain. With or, a true left operand settles the result, so the right operand is never evaluated. With and, a false left operand settles it the same way. The practical benefit is that the left operand can guard the right one — for example count != 0 and total / count > 10 never performs the division when count is 0, avoiding a ZeroDivisionError.
  10. Inside vs. outside a range.Inside a range uses and: the value must clear the lower bound and stay under the upper bound. Outside a range uses or: the value is either below the lower bound or above the upper one. Using and for an outside test — temp < 18 and temp > 24 — can never be true, because no single number is simultaneously below 18 and above 24.
  11. Flags.A flag is a Boolean variable that signals whether a condition has occurred. It is initialized to False before the work begins ("hasn't happened yet"), set to True at the moment the condition is detected, and tested afterward with the variable used bare in the condition — if found:. Naming it after the condition it tracks makes that test read like a sentence.

  1. Step 3 — why boundary values.Values in the middle of a bracket, like 5 or 18, are handled correctly even by a ladder with the wrong comparison operator. The boundaries are exactly where <= and < behave differently, so an off-by-one error only reveals itself there. A weight of exactly 2.0 must land in the first bracket, not the second.
  2. Step 4 — reordering the ladder.A 1 kg package would be charged 15.00. With weight <= 25 first, that condition is true for 1 kg, so the ladder stops there and the cheaper brackets below are never reached. This is the practical consequence of "first true condition wins": the conditions must run from narrowest to broadest.
  3. Step 6 — separate if statements.They would not be mutually exclusive. A 1 kg package satisfies <= 2, <= 10, and <= 25, so three charges would print. The elif ladder is what guarantees exactly one branch runs.   1. Step 5 — chained vs. and.Both produce True; they are exactly equivalent. The explicit and form — age >= 0 and age <= 120 — is the version that works in most other programming languages. The chained form 0 <= age <= 120 reads like ordinary mathematics and is a Python convenience most languages do not allow.
  2. Step 7 — short-circuit evaluation.In the first version the left operand count != 0 is False. Since and cannot be true once either side is false, the outcome is already settled, so Python never evaluates the division and simply returns False. In the reversed version the division is the left operand, so it is evaluated immediately — dividing 50 by 0 raises ZeroDivisionError before the guard on the right is ever reached. The order of the operands is what makes the first version safe: the left side guards the right.

Common error to watch for. Students often write age >= 13 and height >= 120 as age and height >= 13 and 120. That parses without error and produces a misleading result, so it can survive testing — worth calling out in feedback.
