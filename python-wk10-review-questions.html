Short Answer · 2 points each

  1. The two parts.A key and a value. The key must be immutable — a string, number, or tuple — because the dictionary uses the key itself to locate the pair. If a key could change after insertion, the dictionary would no longer be able to find what it stored.
  2. Dictionary vs. list retrieval.A list element is retrieved by its numeric position, which depends on where it sits in the sequence. A dictionary value is retrieved by handing over its key — position is irrelevant. That is why a dictionary is described as a mapping of keys to values rather than a sequence.
  3. Missing key.Python raises KeyError. Two preventions: test first with the in operator and only subscript when the key is present; or use the get method with a default value, which returns the default instead of raising.
  4. Two outcomes of one statement.If the key is absent, the pair is added. If the key is already present, its value is replaced. What determines which happens is only whether the key already exists — the syntax is identical. This means an accidental reuse of a key silently overwrites data instead of adding to it.
  5. What in searches.It searches the keys only. Given slots = {"A1": "pretzels"}, the test "pretzels" in slots returns False even though "pretzels" is in the dictionary — because it is a value, not a key. Testing values requires in slots.values().
  6. Looping.A plain for loop over a dictionary gives one key per pass; the value must then be fetched by subscripting with that key. The items method returns the pairs as tuples, so a loop with two variables receives the key and the value together on each pass — no subscripting needed.
  7. get vs. brackets.Subscripting raises KeyError when the key is missing; get returns a default instead and never raises. Use brackets when a missing key genuinely signals a bug you want reported, and get when a missing key is a normal possibility the program should handle smoothly.
  8. Three set rules.Every item is unique (no duplicates); the items are unordered (no first or last, and no indexing); and the items may be of different types. Uniqueness is what makes sets ideal for removing duplicates — passing a list with repeats to set() collapses them automatically.
  9. remove vs. discard.Both remove one item, but remove raises a KeyError if the item is not present while discard does nothing. discard is the safer default; reach for remove only when a missing item indicates a bug you would want to hear about.
  10. The four operations.Union — everything in either set. Intersection — only items in both. Difference — items in the first that are not in the second. Symmetric difference — items in one or the other but not both. Difference is the order-dependent one: A - B asks what is in A only, while B - A asks what is in B only — two different questions.
  11. Serializing.Converting an object into a stream of bytes that can be written to a file and later read back and rebuilt into an equivalent object. In Python it is called pickling, done with the pickle module. A program needs it because objects built in memory vanish when the program ends — pickling lets a whole dictionary or set persist between runs without writing conversion code by hand.

Algorithm Workbench · 1 point each

  1. Create the dictionary.slots = {"A1": "pretzels", "A2": "almonds", "B1": "raisins"}

Step 3 — what get does.It supplies the value 0 for a word that has never been seen, so the very first occurrence is treated exactly like any later one: fetch the current count (0 if absent), add 1, store it back. The if-else existed only to handle the first occurrence as a special case, and get removes that special case — collapsing four lines to one.
  2. Step 4 — items vs. plain loop.Looping over the dictionary directly gives one key per pass, so the value must be fetched with freq[word]. items() yields each pair as a tuple, so two loop variables receive the key and the value together — no second lookup, and the intent reads more clearly.
  3. Step 5 — why a set.8 distinct words out of 11 total. len(set(words)) gives the distinct count because uniqueness is a defining rule of sets — passing the list to set() collapses every repeat automatically, with no loop and no comparison logic. Accept also len(freq), since dictionary keys are unique too; credit either with reasoning.
  4. Step 7 — two safe ways, and which in a loop.freq["cat"] raises KeyError: 'cat'. Safe ways: freq.get("cat", 0), which returns the default; or guard with if "cat" in freq: before subscripting. Inside a loop, get is preferable — it is a single expression, avoids a branch on every pass, and returns a usable value directly rather than requiring a separate lookup after the test.

>>> python_roster | java_roster

QuestionOperationResult

  1. Step 3 — order dependence.java_roster - python_roster is {'Ravi'}, not {'Maya', 'Theo'}. Union, intersection, and symmetric difference are order-independent — they ask a symmetric question. Difference is not, because "in A but not B" and "in B but not A" are genuinely different questions.
  2. Step 4 — the second add.The length is 5 after the first add and still 5 after the second — nothing happened. The uniqueness rule means a set holds at most one copy of any item, so adding a duplicate is silently harmless. A useful consequence: you never need to check whether an item is already present before adding it.
  3. Step 5 — which remover.remove raises KeyError: 'Jordan'; discard does nothing at all. For a program removing a student who may or may not be enrolled, discard is correct — absence is an expected condition, not an error. remove would crash on a perfectly normal case.
  4. Step 6 — which is the subset.required.issubset(completed) → True. required is the subset: every required skill appears among the completed ones. If completed were missing "riveting", the answer would become False — which is exactly the point of the test, since a subset check answers "is anything required still missing?" in one call.
  5. Step 7 — the file modes."wb" for writing and "rb" for reading. They differ from Week 07's "w" and "r" by the b, which opens the file in binary mode. Pickle does not write readable text — it writes a byte stream — so the file must be opened as binary in both directions. Using text mode raises an error or corrupts the data.
