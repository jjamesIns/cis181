Exercise 1

Temperature Conversion Toolkit

Build a small set of functions that work together — one that returns a value, one that returns a string, and one that ties them into a report. This is top-down design in miniature.

  1. Write a value-returning function to_celsius(fahrenheit) that returns (fahrenheit - 32) * 5 / 9. Call it with 212 and confirm you get 100.0.
  2. Test it with 98.6, 32, and -40, displaying each result to two decimal places with an f-string. Explain: the result for -40 is unusual. What is it, and why does it happen?
  3. Write a second value-returning function describe(celsius) that returns the string 'freezing' when the temperature is 0 or below, 'cold' below 15, 'mild' below 27, and 'hot' otherwise. Use an if-elif-else ladder.
  4. Write a void function report(fahrenheit) that calls both of the other functions and displays one line such as 70 F = 21.11 C (mild). Call report(70).
  5. Explain: report is a void function while the other two are value-returning. Explain why that division of labor is the right one here, and what you would lose if to_celsius printed the result instead of returning it.
  6. Now try to break scope on purpose. Inside to_celsius, the result is stored in a local variable before being returned. After calling the function, type that variable's name alone at the prompt. Record exactly what happens. Explain: name the error and say why it occurs.
  7. Add a global constant FREEZING_F = 32 above your functions and rewrite to_celsius to use it in place of the literal 32. Explain: why does this function not need the global keyword?

Short Answer · 2 points each

  1. Four advantages of modularizing.Simpler code, because each function is short enough to reason about on its own; code reuse, since the logic is written once and called from anywhere; better testing and debugging, because functions can be tested in isolation so a failure points to a known place; and faster development and teamwork, since different people can write different functions simultaneously.
  2. Two parts of a function definition.The function header — the first line, containing def, the function name, parentheses, and a colon. And the block — the indented statements below it that make up the function's body.
  3. End of the block.The function returns: the interpreter jumps back to the part of the program that called the function and resumes execution at the statement immediately after the call.
  4. Void vs. value-returning.A void function executes its statements and simply ends without sending a value back — print is the standard example, and it is called as a statement on its own line. A value-returning function sends a value back to the caller, which is used in an expression or assignment — input, int, and float are examples.
  5. Local variable and scope.A local variable is one created (assigned a value) inside a function; only statements inside that same function can access it. Its scope is the function in which it was created, and only from the point of its creation onward — a statement earlier in the same function cannot use it.
  6. Argument vs. parameter.An argument is the piece of data you send into a function at the call, written inside the parentheses. A parameter is the variable listed in the function header that receives that value. Both refer to the same value; the argument is what is passed, the parameter is what receives it.
  7. Pass by value.The function receives a copy of the argument's value rather than the original variable. The consequence is that reassigning the parameter inside the function has no effect on the caller's variable — communication flows one way, from caller into function, so a void function cannot hand results back by modifying its parameters.
  8. Two problems with globals.Any two of: debugging is harder because many places in the code could be changing the value; functions that depend on globals are hard to reuse in another program, since the global must come with them; and the program as a whole becomes harder to understand.
  9. Global constants.A global name whose value is never changed. It avoids the problems of global variables precisely because nothing reassigns it, so there is no hunting for what modified it. Python has no true constants, so you simulate one by creating a global variable, writing its name in ALL_CAPS by convention, and never reassigning it inside any function.
  10. Boolean function.A function that returns True or False. It is useful when the same test is needed in several places — you call the function instead of repeating the logic — and it tidies up complicated input validation by giving a messy condition a readable name.
  11. Random from 0, 5, 10 … 30.random.randrange(0, 35, 5). The limit must be 35, not 30, because randrange follows the same rule as range and excludes the ending limit — with 30 the value 30 could never be chosen.

Algorithm Workbench · 1 point each

  1. times_five.def times_five(number): with the body print(number * 5). Note the question says "display," so a print is correct here, not a return.
  2. Call show_total.show_total(25)
  3. Positional matching.a = 7, b = 4, c = 9 — arguments are matched to parameters by position.
  4. Trace 1.Three lines: 5 2.5 · 0 0 · 5 2.5. The function reassigns its own parameters, but because Python passes by value, x and y in main are untouched. Students who answer 0 0 for the third line have missed pass-by-value — this is the key item in the section.
  5. show_area.def show_area(width, height): with print(width * height), called as show_area(8, 3) → displays 24.
  6. Keyword arguments.book_room(guests=2, nights=3) — with keywords the order does not matter, so book_room(nights=3, guests=2) is equally correct.
  7. Scope bug.A NameError. The variable greeting is local to show_message, so it ceases to exist once that function returns and main cannot see it. Fixes: make show_message return the string and have main capture it, or move the print inside show_message. Declaring it global also works but is the worst of the three.
  8. square.def square(number): return number * number, then print(square(7)) → 49.
  9. full_name.def full_name(first, last): return first + " " + last. An f-string return is equally acceptable.
  10. is_even.def is_even(number): return number % 2 == 0. Full credit only if the comparison is returned directly; an if/else returning True/False works but is worth noting as verbose.
  11. split_time.def split_time(total_seconds): computing minutes = total_seconds // 60 and seconds = total_seconds % 60, then return minutes, seconds. Called as m, s = split_time(455) → m = 7, s = 35.
  12. Missing line.global attempts must be the first line of the function body. Without it Python treats attempts as a new local variable, and the statement raises an UnboundLocalError because it tries to read a local that has no value yet.
  13. Random 1–20.import random then roll = random.randint(1, 20) — randint includes both endpoints, so no adjustment is needed.
  14. math values.a. 12.0 · b. 5 · c. 4 · d. 5.0 · e. 3.0
  15. Global constant.TAX_RATE = 0.0875 outside all functions, then def total_with_tax(price): return price + price * TAX_RATE. No global keyword is needed because the function only reads the value — the keyword is required only to reassign a global.
  16. Trace 2.12 — the inner call returns 6, which becomes the argument to the outer call, returning 12. This is a nested function call, the same shape as int(input(...)) from Week 2.

  1. Step 2 — the -40 result.-40 °F equals -40 °C — it is the single point where the two scales coincide. It happens because the conversion is a straight line and -40 is the value where the multiply-and-offset leaves the number unchanged. Accept any answer that identifies it as the crossover point of the two scales.
  2. Step 5 — void vs. value-returning.to_celsius and describe each compute one piece of information, and returning it lets that information be reused — fed into another function, formatted differently, or stored. report performs an action rather than computing a value, so it has nothing to hand back. If to_celsius printed instead of returning, its answer could never be passed to describe or formatted by the caller; the function would do exactly one thing in exactly one format and could not be composed with anything else.
  3. Step 6 — the scope error.NameError: name 'result' is not defined. result is a local variable inside to_celsius; its scope is that function only, and it ceases to exist the moment the function returns. The value came back through the return statement, but the variable holding it did not.

Exercise 2 · Dice Roller and the Seed — 14 points

interactive mode
>>> import random
>>> def roll_two():
...     return random.randint(1, 6) + random.randint(1, 6)
...
>>> def is_doubles(a, b):
...     return a == b
...
>>> is_doubles(4, 4)
True
>>> is_doubles(2, 5)
False
>>> random.seed(7)
>>> [random.randint(1, 6) for i in range(5)]
[3, 2, 4, 6, 1]
>>> random.seed(7)
>>> [random.randint(1, 6) for i in range(5)]
[3, 2, 4, 6, 1]
>>> random.randrange(0, 35, 5)
10
>>> import math
>>> math.sqrt(144)
12.0
>>> math.ceil(4.1)
5
>>> math.floor(4.9)
4
>>> print(f"{math.pi:.4f}")
3.1416
On the seeded values. Students' unseeded rolls in steps 1–3 will all differ — that is the point. The seeded rolls in step 4 should be identical to each other; the specific sequence shown above is what CPython produces, but grade on whether the two sets match, not on the particular numbers.
  1. Step 2 — smallest and largest.Smallest 2 (1 + 1), largest 12 (6 + 6). Each die independently returns 1 through 6 inclusive, since randint includes both endpoints.
  2. Step 4 — the two seeded sets.They are identical. The numbers are not truly random but pseudo-random: they are produced by a formula, and the seed initializes that formula. Reset the seed to the same value and the formula restarts from the same place, producing the same series. By default Python seeds from the system clock, which is why each ordinary run differs.
  3. Step 5 — useful vs. serious mistake.Useful: testing and debugging, where a reproducible sequence lets you re-run a simulation or a game and get identical results, or grading, where every student's program should produce the same output. A serious mistake: anything requiring unpredictability — shuffling a card deck in a real game, or generating passwords, security tokens, or lottery numbers, where a fixed seed makes the entire sequence predictable to anyone who knows it.
  4. Step 6 — randrange arguments.random.randrange(0, 35, 5) — start 0, limit 35, step 5. The limit is 35 rather than 30 because randrange excludes its ending limit exactly as range does; with 30 the value 30 could never be selected.
  5. Step 7 — why 12.0 and not 12.The trailing .0 shows the value is a float, not an int. math.sqrt always returns a floating-point number, even when the root is a whole number, because most square roots are not whole. Worth contrasting with ceil and floor, which return true integers.

3Steps 1–3: module imported, roll_two returns a sum, is_doubles returns a Boolean directly.
2Step 2 — range of 2 through 12 with reasoning.
3Step 4 — both seeded sets recorded and shown identical, with pseudo-random correctly explained.
2Step 5 — one sound use and one sound misuse of a fixed seed.
2Step 6 — randrange(0, 35, 5) with the excluded-limit reasoning.
2Step 7 — all four math values correct, and the float return type identified.
Common error to watch for. Writing randint(1, 6) * 2 for roll_two. It produces a number in the right range but can only ever yield even values — a good illustration that two independent calls are not the same as one call doubled.
