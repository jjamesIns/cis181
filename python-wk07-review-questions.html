True or False

10 × 1 pt = 10
  1. T / F

    Data stored in variables survives after the program ends.

  2. T / F

    Opening an existing file in 'w' mode erases its contents immediately.

  3. T / F

    Opening a file in 'a' mode raises an error if the file does not already exist.

  4. T / F

    The write method automatically places each item on its own line.

  5. T / F

    The expression "95" + 5 produces the value 100.

  6. T / F

    A for loop can iterate directly over a file object, one line per iteration.

  7. T / F

    A record is made up of one or more fields.

  8. T / F

    Checking whether a file exists before opening it is a completely reliable way to avoid FileNotFoundError.

  9. T / F

    FileNotFoundError is a kind of OSError.

  10. T / F

    If a statement early in a try suite raises an exception, a close() written at the end of that same suite still runs.

Short Answer · 2 points each

  1. Why files?Variables live in RAM, which is wiped clean when the program ends. For data to survive between runs — a saved game, a customer list, last month's readings — it must be written to a file, usually on a disk.
  2. The three steps.Open — connect the program to the file and state whether you intend to read or write. Process — write data to it or read data from it. Close — disconnect, which flushes any pending writes and frees the file for other programs.
  3. File types and access methods.A text file holds data encoded as readable characters; a binary file holds data in the computer's raw internal format, not converted to text. Sequential access reads straight through from beginning to end without skipping; direct (random) access jumps straight to any piece of data in any order. This module uses text files and sequential access throughout.
  4. File object.An object that represents one specific open file and provides the methods used to work with it. A variable references the file object, and the file object is associated with the actual file on disk — so calling a method on the object operates on that file.
  5. 'w' versus 'a'.'w' erases the file's existing contents the moment it opens and starts fresh. 'a' preserves the contents and adds new data at the end. Both create the file if it does not already exist.
  6. The newline.write adds no line breaks, so without '\n' every item runs together on one line. You concatenate it on with +. Coming back, readline includes that newline in the string it returns, so you remove it with rstrip('\n').
  7. Two conversions.Going out, write accepts only strings, so each number must be converted with str. Coming in, every value read from a text file arrives as a string, so it must be converted back with int or float before arithmetic.
  8. End of file.readline returns an empty string, ''. That serves as a sentinel: do a priming read before the loop, loop while line != "":, and read the next line at the bottom of each pass.
  9. Advantage of the for loop.It needs no priming read and no end-of-file test — it hands you one line per pass and stops automatically. That removes the two places the while version most often goes wrong: a forgotten priming read, or a forgotten read at the bottom of the loop.
  10. Record and field.A record is a complete set of data describing one item; a field is a single piece of data within that record. A common approach in a sequential text file is one field per line, written in a fixed order — so reading a record back means reading that same number of lines in that same order.
  11. Why handle rather than check.A file could be deleted or moved in the instant between the existence check and the open, so the check guarantees nothing. Attempting the operation and handling FileNotFoundError covers every case, including the ones a check cannot see.

Algorithm Workbench · 1 point each

  1. Open for writing.outfile = open("notes.txt", "w")
  2. Open for reading, and close.infile = open("notes.txt", "r") then infile.close()
  3. Write three cities.Three calls of the form outfile.write("Tokyo\n"), or a loop over a list writing city + "\n". The newline is required for credit.
  4. Write a number.outfile.write(str(level) + "\n") — both the str conversion and the newline are required.
  5. Read and strip.line = infile.readline(), then line = line.rstrip("\n"), then print(line).
  6. for-loop accumulator.total = 0 before the loop, then for line in infile: containing total += float(line) (or int). The conversion is the graded part.
  7. while-loop version.total = 0, line = infile.readline() as the priming read, then while line != "": containing total += float(line) and a second line = infile.readline() at the bottom.
  8. Trace 1.'Tokyo\n' — repr reveals the trailing newline that readline includes. Answering Tokyo shows the newline was missed; that is the point of using repr.
  9. Trace 2.The file now contains only Oslo followed by a newline. Opening in 'w' mode erased Tokyo, Cairo, and Lima the instant the file was opened — before anything was written.
  10. Trace 3.It displays 955. Both operands are strings, so + performs concatenation rather than addition. Note the related failure: "95" + 5 raises TypeError instead.
  11. Handling a missing file.try: / infile = open("data.txt", "r") / except FileNotFoundError: / print("That file isn't there.")
  12. Second except clause.Add except ValueError: with its own message, after the FileNotFoundError clause. Both clauses attach to the same try.
  13. Guaranteed close.Move the open above the try, put the read and conversion inside the try, and put infile.close() in a finally suite. The open stays outside because if it fails there is nothing to close.
  14. Write a record.Open players.txt for writing, then outfile.write("Rey\n"), outfile.write(str(7) + "\n"), outfile.write(str(2480) + "\n"), then close.
  15. Read a record.name = infile.readline().rstrip("\n"), level = int(infile.readline()), score = int(infile.readline()). The name needs stripping; the numbers do not, because int tolerates surrounding whitespace.
  16. Name the exceptions.a. FileNotFoundError · b. ValueError · c. TypeError

Exercise 1 · The Sensor Readings File — 14 points

interactive mode
>>> outfile = open("readings.txt", "w")
>>> for r in [18.5, 22.0, 19.75]:
...     outfile.write(str(r) + "\n")
...
>>> outfile.close()
>>> outfile = open("readings.txt", "a")
>>> outfile.write("24.5\n")
>>> outfile.close()
>>> infile = open("readings.txt", "r")
>>> print(infile.read())
18.5
22.0
19.75
24.5
>>> infile.close()
>>> infile = open("readings.txt", "r")
>>> total = 0.0
>>> count = 0
>>> for line in infile:
...     total += float(line)
...     count += 1
...
>>> infile.close()
>>> print(f"{count} readings, total {total:.2f}, average {total/count:.2f}")
4 readings, total 84.75, average 21.19
  1. Step 1 — the two things.A str conversion and a newline. Without str, write raises a TypeError because it accepts only strings. Without '\n', the program runs fine but all four values are concatenated onto a single line — 18.522.019.7524.5 — which cannot be read back as separate values.
  2. Step 3 — 'w' instead of 'a'.Opening in 'w' would have erased the three readings immediately, leaving only 24.5 in the file. The erasure happens when the file is opened, not when something is written.
  3. Step 5 — the conversion.float (or int for whole numbers). Omitting it makes total += line attempt to add a string to a number, raising TypeError: unsupported operand type(s) for +=: 'float' and 'str'. Accept a close paraphrase of the message.
  4. Step 6 — the sentinel and the comparison.readline returns an empty string, '', at end of file — not None. Most students prefer the for version: no priming read, no end-of-file test, and no chance of forgetting the read at the bottom of the loop, which is the classic way the while version becomes infinite.

4Steps 1–3: writes with str and '\n', appends correctly, reads back all four values.
3Step 4: for loop accumulates count, total, and average, formatted to two decimals.
2Step 1 explanation — both the conversion and the newline, with the consequence of omitting each.
2Step 3 explanation — 'w' would have erased the earlier readings.
1Step 5 — conversion error reproduced and named.
2Step 6 — working while version, with the empty string identified as the sentinel.

Exercise 2 · The Player Records File — 14 points

interactive mode
>>> outfile = open("players.txt", "w")
>>> for name, level, score in [("Rey",7,2480), ("Finn",4,1120), ("Poe",9,3050)]:
...     outfile.write(name + "\n")
...     outfile.write(str(level) + "\n")
...     outfile.write(str(score) + "\n")
...
>>> outfile.close()
>>> infile = open("players.txt", "r")
>>> while True:
...     name = infile.readline()
...     if name == "":
...         break
...     name = name.rstrip("\n")
...     level = int(infile.readline())
...     score = int(infile.readline())
...     print(name, "— level", level, "— score", score)
...
Rey — level 7 — score 2480
Finn — level 4 — score 1120
Poe — level 9 — score 3050
>>> infile.close()
>>> open("missing.txt", "r")
FileNotFoundError: [Errno 2] No such file or directory: 'missing.txt'
>>> try:
...     infile = open("missing.txt", "r")
... except FileNotFoundError:
...     print("That file isn't there.")
...
That file isn't there.
# after appending the bad record with level "N/A"
>>> level = int(infile.readline())
ValueError: invalid literal for int() with base 10: 'N/A\n'
  1. Step 2 — why not a for loop.A for loop hands you exactly one line per iteration, but a record spans three lines that must be read together and given different treatment — one stripped as text, two converted to integers. The while form lets you call readline three times per pass and keep the fields aligned with their meanings. Accept: it can be done with a for loop plus a counter, but it is clumsier.
  2. Step 5 — why it isn't a file error.ValueError. The file opened perfectly and the line was read without trouble — the failure was int() refusing the text 'N/A'. It is a data problem that happens to have arrived from a file. This is why file-handling code so often needs both a file exception and a conversion exception handled separately.
  3. Step 6 — why two clauses.The two failures are different types, happen at different points, and deserve different messages: FileNotFoundError means the file is absent and nothing can be read at all, while ValueError means the file was read fine but one record is malformed. A single catch-all would report both with the same message and would also swallow unrelated bugs.
  4. Step 7 — the path that leaks the file.If int() raises a ValueError partway through reading, control jumps immediately to the except clause and every remaining statement in the try suite is skipped — including the close() at the bottom. The file object stays open. A finally suite runs on that path too, so the file is released whether the read succeeded, failed and was handled, or failed and was not.
PointsEarned for
3Step 1: three records written, one field per line, with str on both numeric fields.
3Step 2: reading loop displays all three players with correct types and stops at end of file.
2Steps 3–4: FileNotFoundError reproduced verbatim, then handled so the program continues.
2Step 5: bad record appended, ValueError reproduced and correctly distinguished from a file error.
2Step 6: second except clause added, with a reason for keeping them separate.
2Step 7: finally used, and the leaking path described exactly.
Common error to watch for. Reading the three fields but forgetting rstrip on the name. Nothing appears wrong — the name simply prints with a line break inside it, so the output looks oddly spaced. Comparing such a name to a target string will also silently fail, since "Rey\n" != "Rey".
