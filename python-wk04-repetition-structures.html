Foundation

Why programs repeat

Programs often need to perform the same task many times. You could copy and paste the code, but duplicating it is a bad idea on every count.

  • It makes the program needlessly large.
  • Typing the same thing repeatedly is slow and error-prone.
  • If the logic ever changes, you have to fix it in every copy — and you'll miss one.

A repetition structure — a loop — solves all three. You write the repeated code once, and the computer runs it as many times as needed. Python offers two kinds:

whileCondition-controlled loop▸

Repeats as long as a condition is true. Use it when you don't know in advance how many repetitions you'll need — you just keep going until something changes.

forCount-controlled loop▸

Repeats a specific number of times, once for each item in a sequence. Use it when the number of repetitions is known — five rows, ten students, every item in a list.

Condition-controlled

The while loop

A while loop reads like its plain-English meaning: while this condition is true, keep doing this. It has two parts — a condition that's tested for true or false, and a block of statements that repeats as long as the condition holds.

countdown.py
seconds = 5

while seconds > 0:
    print(seconds)
    seconds = seconds - 1

print("Liftoff!")

This prints 5, 4, 3, 2, 1, then "Liftoff!". Each pass through the body is one iteration. The crucial line is seconds = seconds - 1: without it, seconds would stay at 5 forever and the loop would never stop.

Pretest loop

The while loop is a pretest loop — it checks the condition before each iteration. Two consequences: if the condition is false at the very start, the body never runs even once; and you usually have to set up a variable before the loop so the first test has something to check.

For a loop to ever stop, something inside the body must eventually make the condition false. Here's the general shape:

You can also let a loop run until the user decides to stop, by testing a control variable that the user updates each pass:

log_readings.py
again = "y"

while again == "y":
    reading = float(input("Sensor reading: "))
    print("Logged", reading)
    again = input("Log another? (y/n): ")

print("Done.")

The control variable again is given a starting value of "y" before the loop so the first test passes; inside the loop the user resets it, and the moment they type anything other than "y" the loop ends.

The classic bug

Infinite loops

Every loop must contain, within itself, a way to terminate. If nothing inside a while loop ever makes the condition false, you get an infinite loop — one that repeats until the program is forcibly interrupted.

oops.py
seconds = 5

while seconds > 0:
    print(seconds)
    # forgot to decrement seconds — it stays 5 forever

Because seconds never changes, seconds > 0 is always true and the program prints 5 endlessly. Infinite loops almost always come from forgetting the line that moves the loop toward its stopping point. When you write a loop, make a habit of asking: "What in this body will eventually make the condition false?"

If it happens to you

Stuck in a runaway loop in IDLE or a terminal? Press Ctrl + C to interrupt the program. (In the practice console at the bottom of this page, just hit Reset session.)

Count-controlled

The for loop

When you know how many times to repeat — or want to step through every item in a sequence — reach for a for loop. It's a count-controlled loop: it iterates once for each item in a sequence, no manual counter needed.

scores.py
for score in [88, 92, 75, 99]:
    print("Score:", score)

This runs four times. On each pass, the target variable score is assigned the next item from the list — 88, then 92, then 75, then 99. The target variable is simply the name that receives each item at the start of every iteration; you use it inside the body to do the work.

Two loops, two jobs

A for loop manages its own counting, so you can't accidentally create an infinite for loop over a fixed sequence. A while loop puts you in charge of the condition — more flexible, but you own the responsibility of making it stop.

Generating sequences

The range function

Listing values by hand gets tedious fast. The range function generates a sequence of numbers for you, and it's the usual companion to a for loop. It returns an iterable — an object that produces a sequence of values one at a time.

range takes one, two, or three arguments:

CallProducesMeaning
range(5)0, 1, 2, 3, 4One argument: the ending limit (start defaults to 0).
range(2, 8)2, 3, 4, 5, 6, 7Two arguments: starting value and ending limit.
range(0, 20, 5)0, 5, 10, 15Three arguments: start, limit, and a step value.
range(5, 0, -1)5, 4, 3, 2, 1A negative step counts downward.
The off-by-one trap

range never includes the ending limit. range(5) stops at 4, and range(2, 8) stops at 7. To loop through 1 up to and including 10, you need range(1, 11).

Inside the loop, the target variable holds each generated number, ready to use in a calculation. Here's a small squares table:

squares.py
for n in range(1, 6):
    print(n, "squared is", n ** 2)

And when the program doesn't know the count ahead of time, it can ask the user for the bounds and feed those variables to range — just remember to add 1 to the limit if the upper number should be included:

user_range.py
start = int(input("Start at: "))
end = int(input("End at: "))

for num in range(start, end + 1):
    print(num)
A core pattern

Calculating a running total

Adding up a series of numbers is one of the most common loop jobs. The pattern has two pieces: a loop that reads each value, and an accumulator — a variable that keeps the growing total.

The accumulator starts at 0 before the loop. Each iteration adds the current value to it. When the loop ends, the accumulator holds the final total.

expenses.py
expenses = [42.50, 18.00, 7.25, 30.10]

total = 0.0          # accumulator starts empty
for amount in expenses:
    total = total + amount

print("Total spent:", total)

Watch the accumulator grow: it's 0.0, then 42.50, then 60.50, then 67.75, and finally 97.85. The line total = total + amount is the heart of it — take the old total, add the new value, store it back.

Shorthand

Augmented assignment operators

In the accumulator above, the variable on the left of = also appeared on the right: total = total + amount. That pattern is so common that Python provides augmented assignment operators as shorthand for it.

OperatorExampleEquivalent to
+=score += 10score = score + 10
-=lives -= 1lives = lives - 1
*=price *= 2price = price * 2
/=total /= 4total = total / 4
%=n %= 7n = n % 7

So the accumulator line becomes simply total += amount, and the countdown's seconds = seconds - 1 becomes seconds -= 1. Same behavior, less typing, and the intent reads more clearly.

Knowing when to stop

Sentinels

Sometimes you're reading a series of values but don't know how many there will be. A sentinel is a special value that marks the end of the sequence. When the loop reads the sentinel, it knows the data is finished and stops.

A sentinel must be distinctive enough that it can never be mistaken for a real data value. If you're reading test scores, which are always 0 or higher, then -1 makes a safe sentinel — no real score could ever be negative.

scores_total.py
total = 0
score = int(input("Enter a score (-1 to finish): "))

while score != -1:
    total += score
    score = int(input("Enter a score (-1 to finish): "))

print("Total of all scores:", total)

Notice the structure: one input before the loop (the priming read) gives the first test something to check, and a matching input at the bottom of the loop fetches the next value. The sentinel -1 is never added to the total — the loop exits the moment it's seen.

Choosing a sentinel

The right sentinel depends on the data. For positive-only numbers, a negative works. For reading lines from a file, an empty line often serves. The rule never changes: it must be a value that can't legitimately appear in the real data.

Defensive input

Input validation loops

A computer can't tell good data from bad — if a user enters nonsense, the program happily computes a nonsense result. Programmers sum this up as GIGO: garbage in, garbage out. The fix is to inspect input before using it, and refuse to move on until it's valid.

Input validation is usually done with a while loop that repeats as long as the input is bad. Read a value first, then loop: while it fails the check, show an error and read again. Control only leaves the loop once the value is acceptable.

validate_rating.py
rating = int(input("Rate 1 to 5: "))

while rating < 1 or rating > 5:
    print("That's not between 1 and 5.")
    rating = int(input("Rate 1 to 5: "))

print("Thanks! You rated it", rating)

If the first entry is already valid, the loop body never runs — the pretest nature of while means good input passes straight through. Only bad input triggers the error-and-retry cycle.

Loops within loops

Nested loops

A nested loop is a loop contained inside another loop. A digital clock is the classic mental model: for each tick of the hours, the minutes run through all 60 of their values, and for each minute, the seconds run through all 60 of theirs.

A simpler example prints a grid of seat labels — three rows, four seats per row:

seating.py
for row in range(1, 4):          # outer: 3 rows
    for seat in range(1, 5):     # inner: 4 seats
        print("Row", row, "Seat", seat)

Three key facts about nested loops:

  • The inner loop runs through all of its iterations for each single iteration of the outer loop. Row 1 prints seats 1–4, then row 2 prints seats 1–4, and so on.
  • The inner loop finishes faster — it cycles completely before the outer loop advances once.
  • The total number of iterations is the inner count times the outer count. Here that's 4 × 3 = 12 lines printed.

Review

Check yourself

Predict each answer, then open the card. Even better, run it in the console above.

Q1How many numbers does range(1, 6) produce, and what are they?▸

Five: 1, 2, 3, 4, 5. The ending limit 6 is excluded.

Q2What makes a while loop infinite?▸

Nothing in the body ever makes the condition false — most often a forgotten counter update like count -= 1.

Q3Rewrite total = total + price using an augmented operator.▸

total += price.

Q4Why does an accumulator start at 0 before the loop?▸

So the first addition has a known starting point. Starting it inside the loop would reset the total to 0 on every pass, wiping out the running sum.

Q5An outer loop runs 5 times; its inner loop runs 3 times. How many total iterations?▸

15 — inner count times outer count (3 × 5).

Q6Why must a sentinel be a value that can't appear in the real data?▸

Because the loop stops the instant it sees the sentinel. If a legitimate value matched it, the loop would quit early and skip real data.

Reference

Key terms

repetition structure
A loop — a structure that repeats a block of code as many times as needed.
condition-controlled loop
A loop that repeats while a condition is true; written with while.
count-controlled loop
A loop that repeats a set number of times, once per item in a sequence; written with for.
iteration
One single execution of the body of a loop.
pretest loop
A loop that tests its condition before each iteration, so the body may run zero times.
infinite loop
A loop with no way to stop, because its condition never becomes false.
target variable
The variable a for loop assigns each sequence item to on every pass.
iterable
An object that yields a sequence of values one at a time, such as a range.
accumulator
A variable that builds up a running total across the iterations of a loop.
augmented assignment
Shorthand operators (+= -= *= /= %=) that update a variable using its own value.
sentinel
A distinctive value that marks the end of a sequence and stops the loop.
input validation
Checking input before using it, re-prompting until it is acceptable.
GIGO
"Garbage in, garbage out" — bad input produces bad output.
nested loop
A loop placed inside another loop; the inner loop completes fully on each outer pass.
