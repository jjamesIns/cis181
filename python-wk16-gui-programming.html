Until now your programs have run in a console, asking for input in a fixed order. How the user meets the program

Graphical user interfaces

A user interface is the part of a program the user interacts with. Two broad styles exist. A command line interface shows a prompt and waits for the user to type a command. A graphical user interface (GUI) lets the user interact through graphical elements on the screen — windows, buttons, text fields, menus, and dialog boxes.

The deeper difference is about who is in control. A console program decides the order things happen in: it asks for the first input, then the second, and the user can only answer in that order. A GUI is event-driven — the program builds the interface and then waits. The user causes events (a click, a keystroke), and the program responds to each event as it arrives, in whatever order the user chooses.

Dialog boxes — small windows that present information or ask the user to make a choice — handle much of this interaction, alongside icons, buttons, and other controls.

Python's built-in toolkit

Using the tkinter module

Python has no GUI features built into the language itself, but the standard library ships with tkinter, a module for building simple GUIs. A widget is any graphical element a program presents — a label, a button, a text field, and so on.

Most programmers build GUIs with an object-oriented approach: write a class whose __init__ method constructs the window and all its widgets. Creating an instance of the class then makes the window appear. The call to mainloop hands control to tkinter, which waits for and dispatches events.

window_skeleton.py
import tkinter

class HelloWindow:
    def __init__(self):
        # Create the main window.
        self.window = tkinter.Tk()
        # ... build and pack widgets here ...
        # Hand control to tkinter's event loop.
        tkinter.mainloop()

# Creating the object makes the window appear.
app = HelloWindow()

Putting text on the screen

Label widgets and pack

A Label widget displays a single line of text. You create one as an instance of tkinter.Label: the first argument is the container it belongs to (here the main window), and the text argument is what it shows.

Creating a widget isn't enough to make it visible — you must also call its pack method, which positions the widget and displays it. The side argument controls placement: side='top' (the default) stacks widgets vertically, while side='left' and side='right' arrange them horizontally, in the order they were packed.

greeting.py
import tkinter

class GreetingWindow:
    def __init__(self):
        self.window = tkinter.Tk()
        self.line1 = tkinter.Label(self.window, text='Welcome aboard.')
        self.line2 = tkinter.Label(self.window, text='All systems ready.')
        self.line1.pack()        # stacked top-to-bottom (the default)
        self.line2.pack()
        tkinter.mainloop()

app = GreetingWindow()
Grouping widgets

Organizing widgets with frames

A Frame is a container that holds other widgets. Frames are how you arrange groups of widgets independently: pack some labels into one frame and they follow that frame's layout, separate from widgets in another frame. To place a widget in a frame, pass the frame — not the main window — as the widget's container.

panels.py
class PanelWindow:
    def __init__(self):
        self.window = tkinter.Tk()
        self.top = tkinter.Frame(self.window)
        self.bottom = tkinter.Frame(self.window)

        # In the top frame, labels stack vertically.
        tkinter.Label(self.top, text='Engine').pack()
        tkinter.Label(self.top, text='Hydraulics').pack()
        tkinter.Label(self.top, text='Avionics').pack()

        # In the bottom frame, the same labels sit side by side.
        tkinter.Label(self.bottom, text='Engine').pack(side='left')
        tkinter.Label(self.bottom, text='Hydraulics').pack(side='left')
        tkinter.Label(self.bottom, text='Avionics').pack(side='left')

        self.top.pack()
        self.bottom.pack()
        tkinter.mainloop()
Making things happen

Buttons and info dialogs

A Button is a widget the user clicks to make something happen. When you create one you give it the text to show on its face and a command — the function or method to run when it is clicked. That function is called a callback function, or event handler.

An info dialog box is a small pop-up window that shows the user a message. You display one with tkinter.messagebox.showinfo(title, message) — title appears in the dialog's title bar, message in its body.

A quit button closes the program. Rather than writing your own handler, you can set the window's own destroy method as the button's command: clicking the button destroys the window and the program ends.

buttons.py
import tkinter
import tkinter.messagebox

class ButtonWindow:
    def __init__(self):
        self.window = tkinter.Tk()
        self.run_button = tkinter.Button(self.window, text='Run check',
                                         command=self.show_status)
        self.quit_button = tkinter.Button(self.window, text='Quit',
                                          command=self.window.destroy)
        self.run_button.pack()
        self.quit_button.pack()
        tkinter.mainloop()

    # A callback (event handler): runs when the button is clicked.
    def show_status(self):
        tkinter.messagebox.showinfo('Status', 'All systems nominal.')

app = ButtonWindow()
Pass the function, don't call it

Notice command=self.show_status with no parentheses. You're handing tkinter the function itself, to call later when the click happens. Writing command=self.show_status() would call it immediately, at build time, and pass its return value instead — a very common beginner mistake.

Reading what the user types

Getting input with the Entry widget

An Entry widget is a rectangular box the user can type one line of text into. It is the usual way to gather input in a GUI. Typically a button sits nearby; the button's callback reads the entry, processes the value, and shows a result.

To read what the user typed, call the Entry widget's get method. It always returns a string, so if you need a number you must convert it — here with float.

converter.py
class WeightConverter:
    def __init__(self):
        self.window = tkinter.Tk()
        self.prompt = tkinter.Label(self.window, text='Weight in pounds:')
        self.entry = tkinter.Entry(self.window, width=10)
        self.button = tkinter.Button(self.window, text='Convert',
                                     command=self.convert)
        self.prompt.pack(side='left')
        self.entry.pack(side='left')
        self.button.pack(side='left')
        tkinter.mainloop()

    def convert(self):
        pounds = float(self.entry.get())     # get() always returns a string
        kilos = pounds * 0.453592
        tkinter.messagebox.showinfo('Result', f'{pounds} lb = {kilos:.2f} kg')

When the user types a weight and clicks Convert, the callback reads the entry, computes the result, and pops up an info dialog with the answer.

Output without a pop-up

Using labels as output fields

Instead of interrupting the user with a dialog box, you can show results right in the window by updating a Label. The clean way to do this uses tkinter's StringVar class.

Create a StringVar object and attach it to a Label with the textvariable argument. After that, whatever value you store in the StringVar with its set method appears in the Label automatically — no need to rebuild the widget.

live_converter.py
class LiveConverter:
    def __init__(self):
        self.window = tkinter.Tk()
        self.prompt = tkinter.Label(self.window, text='Weight in pounds:')
        self.entry = tkinter.Entry(self.window, width=10)

        # A StringVar drives the output label.
        self.result = tkinter.StringVar()
        self.output = tkinter.Label(self.window, textvariable=self.result)

        self.button = tkinter.Button(self.window, text='Convert',
                                     command=self.convert)
        self.prompt.pack()
        self.entry.pack()
        self.output.pack()
        self.button.pack()
        tkinter.mainloop()

    def convert(self):
        pounds = float(self.entry.get())
        kilos = pounds * 0.453592
        self.result.set(f'{kilos:.2f} kg')   # the label updates automatically
StringVar vs. a plain string

A plain string can't notify the Label that it changed. A StringVar is a tkinter object the Label watches: calling set on it pushes the new text into the Label on screen. The same pattern with IntVar backs the radio and check buttons in the next section.

Letting the user choose

Radio buttons and check buttons

A radio button is a small circle, filled when selected and empty when not. Radio buttons are for choosing one option from several: they are mutually exclusive, so within a group only one can be selected at a time. You create them with tkinter.Radiobutton.

The trick that makes a group mutually exclusive is sharing a single IntVar object. Associate every radio button in the group with the same IntVar, and give each one a unique value. When the user selects a button, its value is stored in the shared IntVar — which automatically deselects the others. Setting the IntVar yourself chooses a default.

A check button is a small box with a label; a check mark shows when it is selected. Check buttons are not mutually exclusive — the user may turn on any combination. So each Checkbutton gets its own IntVar.

choices.py
class CabinWindow:
    def __init__(self):
        self.window = tkinter.Tk()

        # One IntVar shared by the group -> mutually exclusive.
        self.cabin = tkinter.IntVar()
        self.cabin.set(1)                     # a default selection
        tkinter.Radiobutton(self.window, text='Economy',
                            variable=self.cabin, value=1).pack(anchor='w')
        tkinter.Radiobutton(self.window, text='Business',
                            variable=self.cabin, value=2).pack(anchor='w')
        tkinter.Radiobutton(self.window, text='First',
                            variable=self.cabin, value=3).pack(anchor='w')

        # Each check button gets its own IntVar -> independent toggles.
        self.wifi = tkinter.IntVar()
        self.meal = tkinter.IntVar()
        tkinter.Checkbutton(self.window, text='Add Wi-Fi',
                           variable=self.wifi).pack(anchor='w')
        tkinter.Checkbutton(self.window, text='Add meal',
                           variable=self.meal).pack(anchor='w')

        tkinter.mainloop()

You can also give a radio or check button a command argument. That callback runs the instant the button's state changes, so the program can react immediately instead of waiting for the user to click a separate "OK."

A list to choose from

Listbox widgets

Radio buttons work well for a handful of choices, but they take one line of code and one row of space per option. A Listbox shows many items in a compact scrollable box and lets the user pick from them — the right tool when the choices are numerous or come from data your program loaded.

You create an empty Listbox, then fill it by calling insert once per item. The first argument is the position; passing tkinter.END means "add it after everything already there," which is how you build a list in order:

systems_list.py
import tkinter
import tkinter.messagebox

class SystemPicker:
    def __init__(self):
        self.window = tkinter.Tk()

        self.systems = tkinter.Listbox(self.window, height=4)
        # Fill the list -- END means "append at the bottom"
        self.systems.insert(tkinter.END, 'Engine')
        self.systems.insert(tkinter.END, 'Hydraulics')
        self.systems.insert(tkinter.END, 'Avionics')
        self.systems.insert(tkinter.END, 'Landing gear')

        self.button = tkinter.Button(self.window, text='Check system',
                                      command=self.show_choice)
        self.systems.pack()
        self.button.pack()
        tkinter.mainloop()

Reading the user's choice takes two steps, and this is where the widget differs from everything before it. The curselection method does not return the selected text — it returns a tuple of index numbers. You take an index from that tuple, then pass it to get to retrieve the item itself:

reading the selection
    def show_choice(self):
        picked = self.systems.curselection()   # a TUPLE of indexes, e.g. (2,)

        if len(picked) == 0:                    # nothing selected -- guard first!
            tkinter.messagebox.showinfo('Choose', 'Select a system first.')
        else:
            index = picked[0]                    # the first selected index
            name = self.systems.get(index)     # get() turns index into text
            tkinter.messagebox.showinfo('Checking', f'Running {name} diagnostics.')

app = SystemPicker()
The guard is not optional

If nothing is selected, curselection() returns an empty tuple (). Writing picked[0] without checking first raises IndexError: tuple index out of range — and since the user opens your window with nothing selected, that is the very first thing they can make happen. Always test the length before indexing.

Other useful Listbox methods

CallWhat it does
insert(index, item)Adds an item at that position; tkinter.END appends to the bottom.
get(index)Returns the item at that index as a string.
get(first, last)Returns a tuple of the items in that range, inclusive of both ends.
curselection()Returns a tuple of the indexes currently selected — empty if none.
size()Returns how many items the list holds.
delete(index)Removes the item at that index.
delete(0, tkinter.END)Clears the entire list — useful before reloading it with new data.
Filling a Listbox from a list

Because insert is an ordinary method call, a loop can fill the widget from any Python list — including one read from a file. That is the real advantage over radio buttons: the choices do not have to be known when you write the code.

from_data.py
        parts = ['Bolt', 'Bracket', 'Gasket', 'Fairing']
        for item in parts:
            self.parts_list.insert(tkinter.END, item)
A surface to draw on

Drawing with the Canvas widget

The Canvas widget is a blank rectangular area for drawing simple 2-D shapes. You place shapes using its screen coordinate system: the pixel in the upper-left corner is (0, 0), X increases to the right, and Y increases downward — the opposite of the y-axis in math class.

You create a Canvas like any widget, giving it a width and height, then call its drawing methods. The common ones:

MethodDraws
create_line(x1, y1, x2, y2)A line from a start point to an end point.
create_rectangle(x1, y1, x2, y2)A rectangle from its upper-left to its lower-right corner.
create_oval(x1, y1, x2, y2)An oval that fills the given bounding box.
create_arc(x1, y1, x2, y2, start=, extent=)A slice of an oval, from a starting angle through an extent.
create_polygon(x1, y1, x2, y2, ...)A many-sided shape; it closes back to the first point automatically.
create_text(x, y, text=)A string centered at the given point.
shapes.py
class ShapeWindow:
    def __init__(self):
        self.window = tkinter.Tk()
        self.canvas = tkinter.Canvas(self.window, width=240, height=240)

        self.canvas.create_line(0, 0, 240, 240)        # corner to corner
        self.canvas.create_rectangle(40, 40, 200, 200)
        self.canvas.create_oval(60, 60, 180, 180)
        self.canvas.create_text(120, 120, text='Center')

        self.canvas.pack()
        tkinter.mainloop()

Review

Check yourself

Predict each answer, then open the card. Even better, try the logic in the console above.

Q1What does it mean that a GUI program is "event-driven"?▸

The program builds the interface and then waits. The user decides the order of things by causing events — clicks, keystrokes — and the program responds to each event as it happens, rather than dictating a fixed input sequence the way a console program does.

Q2How does a command line interface differ from a graphical user interface?▸

A command line interface shows a prompt and the user types commands. A GUI lets the user interact through on-screen graphical elements — windows, buttons, text fields, dialog boxes — usually with a mouse as well as the keyboard.

Q3You create a Label but it never appears. What did you most likely forget?▸

The call to pack. Creating a widget isn't enough — pack (called on the widget) positions it and makes it visible. The side argument then controls whether widgets stack vertically or line up horizontally.

Q4What is a callback function, and why is it written command=self.handler with no parentheses?▸

A callback (event handler) is the function that runs when the user acts on a widget. You pass the function object so tkinter can call it later, at click time. Adding parentheses would call it immediately during setup and pass its return value instead.

Q5What type does an Entry widget's get method return, and what must you do to do math with it?▸

It always returns a string. To treat the input as a number you must convert it first — for example float(self.entry.get()) or int(...) — before doing arithmetic.

Q6How do a group of radio buttons become mutually exclusive?▸

They all share one IntVar object, and each is given a unique value. Selecting one stores its value in the shared IntVar, which automatically deselects the rest. Setting the IntVar in code chooses a default.

Q7How do check buttons differ from radio buttons, and how does that change the code?▸

Check buttons are independent — the user can select any combination, so they are not mutually exclusive. Because of that, each Checkbutton gets its own IntVar, rather than sharing one as a radio group does.

Q8On a Canvas, where is the point (0, 0), and which direction does the Y coordinate increase?▸

(0, 0) is the upper-left corner. X increases to the right and Y increases downward, so a larger Y value is lower on the screen — the reverse of a math-class graph.

Q9How do you find out which item the user selected in a Listbox?▸

Two steps. curselection() returns a tuple of indexes, not the text. Take an index from it — usually [0] — and pass that to get() to retrieve the item. Check the tuple's length first: with nothing selected it is empty, and indexing it raises IndexError.

Reference

Key terms

user interface
The part of a program through which the user interacts with it.
command line interface
A text interface that shows a prompt and runs commands the user types.
graphical user interface (GUI)
An interface built from on-screen graphical elements the user clicks and types into.
event-driven
A program style in which the user's actions, not the code, determine the order of events.
event
An action such as a click or keystroke that the program can respond to.
widget
A graphical element of a GUI, such as a label, button, or text field.
tkinter
Python's standard-library module for building GUIs.
Label
A widget that displays a single line of text or an image.
pack
The method that positions a widget and makes it visible; side sets the direction.
Frame
A container widget that holds and arranges a group of other widgets.
Button
A widget that runs a callback function when clicked.
callback function (event handler)
The function that runs in response to an event such as a button click.
info dialog box
A pop-up window that shows a message, created with showinfo(title, message).
Entry
A widget for a single line of typed input; its get method returns a string.
StringVar
A tkinter object whose value, set with set, is shown automatically in a linked Label.
Radiobutton
A widget for selecting one option from a mutually exclusive group sharing an IntVar.
Checkbutton
An independent on/off widget; each uses its own IntVar.
Canvas
A rectangular widget for drawing 2-D shapes by screen coordinates.
screen coordinate system
The canvas grid with (0,0) at the top-left, X growing right and Y growing down.
Listbox
A widget showing a list of items the user can select from; curselection returns the selected indexes.
