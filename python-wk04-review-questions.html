True or False

10 × 1 pt = 10
  1. T / F

    A while loop always executes its body at least once.

  2. T / F

    Every loop must contain within itself some way to terminate.

  3. T / F

    The range function includes its ending limit in the sequence it generates.

  4. T / F

    A for loop iterating over a fixed sequence cannot accidentally become an infinite loop.

  5. T / F

    The expression range(5, 0, -1) generates the numbers 5, 4, 3, 2, 1.

  6. T / F

    An accumulator should be initialized inside the loop body so it is ready for each iteration.

  7. T / F

    The statement count -= 1 has the same effect as count = count - 1.

  8. T / F

    A sentinel value is added to the running total along with the real data values.

  9. T / F

    If a user's first entry passes an input validation loop's test, the loop body never executes.

  10. T / F

    In a set of nested loops, the outer loop completes all of its iterations before the inner loop begins.

Short Answer · 2 points each

  1. Three reasons not to duplicate code.It makes the program needlessly large; typing the same thing repeatedly is slow and error-prone; and if the logic ever changes you must fix every copy — and one will be missed.
  2. Condition-controlled vs. count-controlled.A condition-controlled loop repeats as long as a condition is true and is used when the number of repetitions isn't known in advance — written with while. A count-controlled loop repeats a specific number of times, once per item in a sequence, and is used when the count is known — written with for.
  3. Pretest loop.The condition is tested before each iteration. Consequence (either one): if the condition is false at the start, the body never runs at all; and a variable usually has to be set up before the loop so the first test has something to evaluate.
  4. Infinite loop.A loop with no way of ending, which repeats until the program is forcibly interrupted. The question to ask about every loop: "What in this body will eventually make the condition false?"
  5. Target variable.The variable named in the for clause that receives each item from the sequence at the start of every iteration. On each pass it holds the next item, and the body uses it to do the work.
  6. The range arguments.With three arguments the order is starting value, ending limit, and step value. With two, it is start and limit; with one, it is the limit alone and the start defaults to 0. The rule: the ending limit is never included — range(1, 11) is needed to reach 10.
  7. Accumulator.A variable that holds a growing total as a loop repeats. It must be initialized before the loop so the first addition has a known starting point; initializing it inside the loop would reset it to 0 on every pass and destroy the running total.
  8. Augmented assignment operators.Shorthand for statements where the variable on the left of = also appears on the right — +=, -=, *=, /=, %=. They mean exactly the same thing as the longer form but require less typing and state the intent more clearly.
  9. Sentinel.A special value that marks the end of a sequence of data. The rule: it must be distinctive enough that it can never be mistaken for a legitimate data value. For test scores, which are always 0 or higher, -1 is a safe choice because no real score could be negative.
  10. Two input statements.The one before the loop is the priming read — it gives the first condition test something to evaluate. The one at the bottom of the body fetches the next value so the condition has fresh data on the following pass. Without the priming read the variable wouldn't exist yet; without the one inside, the same value would be tested forever and the loop would never end.
  11. GIGO.Garbage in, garbage out — a program given bad data will happily produce a bad result, because a computer cannot tell good data from bad. An input validation loop prevents it by inspecting the value and repeating an error-and-retry cycle until the input is acceptable, so no invalid value ever reaches the calculation.

Algorithm Workbench · 1 point each

  1. Count down from 10.n = 10 then while n > 0: with print(n) and n -= 1 in the body. Deduct if the decrement is missing — that is an infinite loop.
  2. Product loop.A priming read and matching read inside, for example: number = int(input(...)), product = number * 5, then while product < 200: containing a new input, a new product = number * 5. Accept any correct structure where product is recomputed inside the loop.
  3. 0 to 1000 by tens.for n in range(0, 1001, 10): — note the limit must be 1001, not 1000, for 1000 to appear. That produces 101 numbers.
  4. Odd numbers 1–19.for n in range(1, 20, 2): — ten numbers, 1 through 19.
  5. Eight entries, running total.total = 0 before the loop, then for i in range(8): containing an input converted to a number and total += number.
  6. Augmented assignment.a. x += 5 · b. x *= 3 · c. x /= 4 · d. x -= 25 · e. x %= 7
  7. 6 rows of 12 hashes.Outer for row in range(6):, inner for col in range(12): with print('#', end=''), then a bare print() after the inner loop but inside the outer. Accept print('#' * 12) in a single loop as an alternative, but the question asks for nested loops.
  8. Positive nonzero validation.A priming read, then while number <= 0: containing an error message and a re-read.
  9. Range 1–100 validation.A priming read, then while number < 1 or number > 100: containing an error message and a re-read. Note the or — this is an "outside the range" test.
  10. Sentinel-controlled total.total = 0, priming read score = int(input('Enter a score (-1 to finish): ')), then while score != -1: containing total += score and a matching re-read. The sentinel is never added.
  11. Range counts.a. 6 numbers, 0 to 5 · b. 6 numbers, 3 to 8 · c. 4 numbers, 0 to 15 · d. 5 numbers, 10 to 2
  12. Trace 1.15 — the accumulator adds 1+2+3+4+5. Note 6 is excluded.
  13. Trace 2.-2 — count goes 10, 7, 4, 1, then -2. The test happens only between iterations, so it overshoots past 0 rather than stopping at it. Students who answer 0 or 1 have missed that the condition isn't checked mid-body.
  14. Trace 3.6 lines (3 rows × 2 seats), and the first is Row 1 Seat 1.
  15. The bug.Nothing in the body changes seconds, so the condition is always true and the loop prints 5 forever. Add seconds -= 1 as the last line of the body.
  16. Asterisk triangle.for row in range(1, 6): containing for star in range(row): with print('*', end=''), then a bare print() inside the outer loop. The inner range depends on row, which is what makes the rows different lengths.

Step 7 — entering the sentinel immediately:

interactive mode
>>> print(f"Average: {total / count:.2f}")

Accumulator tracetotalcount

  1. Step 1 — why initialize before the loop?The first addition needs a known starting point. If total = 0.0 sat inside the loop it would reset to zero on every pass, so the final "total" would only ever hold the last reading. The same applies to count.
  2. Step 6 — why -999 and not 0?A sentinel must be a value that cannot legitimately appear in the real data. Zero degrees is a perfectly valid temperature reading, so using 0 would silently truncate the data set the moment a real freezing reading was entered. -999 is far outside any plausible temperature, so it can never be confused with real data.
  3. Step 7 — what happened and how to fix it.Entering the sentinel first means the loop body never runs, so count stays 0 and the average calculation divides by zero, raising ZeroDivisionError. The guard is an if-else around the report: if count > 0: display the statistics, else: display a message such as "No readings entered." Accept a short-circuit and guard as an alternative — that connects back to Week 3.

5Working sentinel loop: both accumulators initialized, priming read, augmented assignments, matching read at the bottom.
2Step 5 — count, total, and average all correct and formatted to two decimals.
2Step 1 explanation — initializing inside the loop would reset the total each pass.
2Step 6 explanation — a sentinel must not be a possible real value; 0 is a valid temperature.
3Step 7 — the error reproduced and recorded, correctly diagnosed, with a working guard written.
Common error to watch for. Omitting the second input inside the loop body. The program then tests the same first reading forever — an infinite loop that also never asks for more data. It is the single most common sentinel-loop mistake.

Exercise 2 · Multiplication Table Generator — 14 points

interactive mode
>>> size = int(input("Table size (1-12): "))
Table size (1-12): 0
>>> while size < 1 or size > 12:
...     print("Please enter a value from 1 to 12.")
...     size = int(input("Table size (1-12): "))
...
Please enter a value from 1 to 12.
Table size (1-12): 20
Please enter a value from 1 to 12.
Table size (1-12): 5
>>> for row in range(1, size + 1):
...     for col in range(1, size + 1):
...         print(f"{row * col:4d}", end="")
...     print()
...
   1   2   3   4   5
   2   4   6   8  10
   3   6   9  12  15
   4   8  12  16  20
   5  10  15  20  25
>>> for row in range(1, 6):
...     for star in range(row):
...         print("*", end="")
...     print()
...
*
**
***
****
*****
  1. Step 1 — which entries ran the loop body?0 and 20 were both outside the valid range, so each triggered the error message and a re-read. 5 was valid, so the condition was false and control passed straight out of the loop without the body running again. Because while is a pretest loop, valid input is never penalized.
  2. Step 3 — how many lines for size 5?25 lines. The rule: the inner loop runs completely for each single iteration of the outer loop, so the total is the inner count times the outer count — 5 × 5.
  3. Step 5 — what the bare print() does.The inner loop's print(..., end="") suppresses the newline so the products stay on one line. The bare print() supplies the newline that ends that row. It must be inside the outer loop so it runs once per row, and outside the inner loop so it runs only after a full row of products has been printed. Moved inside the inner loop, it would fire after every single product and the table would collapse into one number per line — 25 lines instead of 5 rows.
  4. Step 6 — what changes for the triangle.The inner loop's range must depend on the outer loop's variable — range(row) instead of a fixed count. Because row increases each pass, the inner loop runs a different number of times per row, producing 1, 2, 3, 4, then 5 asterisks.
PointsEarned for
3Validation loop rejects 0 and 20, accepts 5, and re-prompts correctly.
3Nested loops produce all 25 products using range(1, size + 1).
2Step 4 — grid formatting with end="" and the bare print() placed correctly.
2Step 3 — 25 lines, with the inner-times-outer rule stated.
2Step 5 — explains the newline's role and predicts/confirms the effect of moving it.
2Step 6 — triangle produced, with the dependency on row identified.
