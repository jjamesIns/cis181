Recursion

A recursive function is one that calls itself. That sounds like a recipe for going in circles — and it would be, except that each call works on a smaller version of the problem, steadily shrinking it until the answer is obvious and no more calls are needed. In this chapter we'll see what makes recursion stop, how to spot the two pieces every recursive function needs, and work through the classics: factorials, Fibonacci numbers, the greatest common divisor, and the Towers of Hanoi.

A function that calls itself

Introduction to recursion

A recursive function is a function that calls itself. On its own that would loop forever, so a recursive function must also have a way to control how many times it repeats — usually an if statement that decides, on each call, whether to call itself again or to stop and return a value.

Here is a small recursive function. It counts down from n to 1, then announces liftoff:

countdown.py
# Counts down from n, then announces liftoff.
def count_down(n):
    if n > 0:                   # still counting -- call itself
        print(n)
        count_down(n - 1)       # the recursive call, on a smaller n
    else:                      # nothing left to count -- stop
        print('Liftoff!')

Calling count_down(3) does not finish in one step. It prints 3 and then calls count_down(2), which prints 2 and calls count_down(1), and so on. Each call is a fresh execution of the function with its own value of n. The number of times a function calls itself is called the depth of recursion — here the depth is 3.

Where does control go after a recursive call?

Exactly where it would after any function call: back to the line right after the call. When count_down(0) finishes, control returns to count_down(1), which has no statements left to run, so it returns — and so on back up the chain until the original count_down(3) returns.

Base case and recursive case

Problem solving with recursion

Recursion is a powerful tool for repetitive problems, but it is never required: any problem you can solve recursively can also be solved with a loop. What recursion offers is a way of thinking — "solve a smaller version of the same problem, then build on its answer."

Every well-formed recursive function follows the same two-part outline:

  • The base case. If the problem is small enough to solve directly — with no further recursion — solve it and return the answer.
  • The recursive case. Otherwise, reduce the problem to a smaller problem of the same structure, call the function on that smaller problem, and use its result to build this call's answer.

Because each recursive call makes the problem a little smaller, the function eventually reaches the base case, the recursion stops, and the returns flow back up.

A cost worth knowing

Recursive solutions are usually less efficient than the equivalent loop, because every call carries the overhead of setting up and tearing down a function call. Recursion earns its place when it makes a problem dramatically clearer to express — not by being faster.

A classic recursive definition

Calculating a factorial

The factorial of a nonnegative integer n, written n!, is the product of all integers from 1 up to n. Its mathematical definition is already recursive:

  • For n = 0: n! is defined as 1 — this is the base case.
  • For n > 0: n! equals n × (n - 1)! — this is the recursive case.

That definition translates almost directly into code:

factorial.py
# Returns n! for a nonnegative integer n.
def factorial(n):
    if n == 0:                # base case: 0! is 1
        return 1
    else:                     # recursive case
        return n * factorial(n - 1)

Two ways a function can recur

Direct and indirect recursion

So far every example has used direct recursion: a function that calls itself. There is a second form. In indirect recursion, function A calls function B, and function B (perhaps after a few steps) calls function A — the cycle still comes back around.

Here two functions decide whether a number is even or odd by handing the work back and forth, each subtracting 1 and asking the other:

even_odd.py
# is_even and is_odd call each other -- indirect recursion.
def is_even(n):
    if n == 0:
        return True
    else:
        return is_odd(n - 1)

def is_odd(n):
    if n == 0:
        return False
    else:
        return is_even(n - 1)
Recursion in the wild

Examples of recursive algorithms

Once you can spot the base case and the recursive case, a whole family of problems opens up. Three classics follow.

Summing a list

To add up a list of numbers, take the first element and add it to the sum of all the rest. The list of "all the rest" is smaller, so the problem shrinks with every call; an empty list has a sum of 0, which is the base case.

sum_list.py
# Adds up every number in a list, recursively.
def sum_all(numbers):
    if len(numbers) == 0:          # base case: empty list sums to 0
        return 0
    else:                          # recursive case
        return numbers[0] + sum_all(numbers[1:])

The slice numbers[1:] is the list with its first item removed — the smaller subproblem handed to the next call.

The Fibonacci series

In the Fibonacci series each number is the sum of the two before it: 0, 1, 1, 2, 3, 5, 8, 13, …. This definition needs two base cases, one for each of the first two numbers:

  • fibonacci(0) is 0
  • fibonacci(1) is 1
  • otherwise, fibonacci(n) is fibonacci(n - 1) + fibonacci(n - 2)
fibonacci.py
# Returns the nth number in the Fibonacci series (0-based).
def fibonacci(n):
    if n == 0:
        return 0
    elif n == 1:
        return 1
    else:
        return fibonacci(n - 1) + fibonacci(n - 2)
Two calls per step

Notice the recursive case makes two calls. This mirrors the mathematics beautifully, but it re-computes the same values over and over — fibonacci(30) makes well over a million calls. It is a perfect example of a recursive solution that is clear but not efficient.

The greatest common divisor

The greatest common divisor (GCD) of two positive integers is the largest integer that divides both. Euclid's algorithm states it recursively: if b divides a evenly, the GCD is b; otherwise it is the GCD of b and the remainder of a / b.

gcd.py
# Euclid's algorithm: the greatest common divisor of a and b.
def gcd(a, b):
    if a % b == 0:            # base case: b divides a evenly
        return b
    else:                      # recursive case
        return gcd(b, a % b)

Each call replaces the pair with a smaller pair, so the remainder marches toward 0 and the base case is always reached.

Recursion's showpiece

The Towers of Hanoi

The Towers of Hanoi is a puzzle often used to show off the power of recursion. There are three pegs and a stack of disks of decreasing size, all starting on the leftmost peg. The goal is to move the whole stack to the rightmost peg under three rules:

  • Move only one disk at a time.
  • A larger disk may never rest on a smaller one.
  • Every disk must be on some peg except the one currently being moved.

The recursive insight is to ignore the bottom disk for a moment and think in terms of "the top count - 1 disks." To move count disks from the source peg to the target peg:

  • If there is only one disk, move it straight to the target. (Base case.)
  • Otherwise: move the top count - 1 disks to the spare peg, move the single largest disk to the target, then move those count - 1 disks from the spare peg onto the target.
hanoi.py
# Prints the moves that solve the Towers of Hanoi:
# move `count` disks from source to target, using spare.
def move_disks(count, source, target, spare):
    if count == 1:                              # base case
        print('Move a disk from', source, 'to', target)
    else:                                     # recursive case
        move_disks(count - 1, source, spare, target)
        print('Move a disk from', source, 'to', target)
        move_disks(count - 1, spare, target, source)

Notice how the three peg arguments are passed in different orders on each recursive call — that reshuffling is what makes the spare and target pegs swap roles as the problem unwinds.

When to reach for which

Recursion versus looping

Recursion and looping can solve the same repetitive problems, so the choice is about clarity and cost, not capability.

Reasons to prefer a loop. A loop avoids the overhead of a function call on every repetition, so it is generally more efficient in both time and memory. For many problems — running totals, scanning a list — the loop is also simply the more obvious solution.

Reasons to prefer recursion. Some problems are defined recursively to begin with — factorials, the Fibonacci series, the Towers of Hanoi — and the recursive code reads almost exactly like the definition. There the recursive version is clearer and easier to get right, even if a loop would run faster.

The same factorial, written with a loop, shows the trade-off — faster, but no longer a mirror of the "n × (n-1)!" definition:

factorial_loop.py
# The same factorial, written with a loop instead.
def factorial_loop(n):
    result = 1
    for k in range(2, n + 1):
        result = result * k
    return result
Recursion has a floor

Each recursive call uses a little memory that isn't freed until the call returns. If a recursion never reaches its base case — or simply goes too deep — Python stops it with a RecursionError (the default limit is around 1,000 calls deep). A correct base case that is actually reachable is what keeps that from happening.

Review

Check yourself

Predict each answer, then open the card. Even better, try it in the console above.

Q1What two parts must every well-formed recursive function have?▸

A base case — a condition simple enough to answer directly without recursing — and a recursive case that reduces the problem to a smaller version of itself and calls the function on it. Without the base case the recursion never stops; without the recursive case it isn't recursion.

Q2What happens if a recursive function can never reach its base case?▸

It calls itself endlessly, going deeper and deeper. Each call consumes a little memory, so Python eventually stops it with a RecursionError (the default depth limit is around 1,000). The fix is a base case that the recursive case actually moves toward.

Q3In factorial, identify the base case and the recursive case.▸

Base case: n == 0, which returns 1. Recursive case: any n > 0, which returns n * factorial(n - 1) — the same function applied to a smaller n.

Q4What is the "depth of recursion"?▸

The number of times the function calls itself before reaching the base case — how many calls are stacked up waiting at the deepest point. For count_down(3) the depth is 3.

Q5Why is a recursive solution usually less efficient than the equivalent loop?▸

Every recursive call carries the overhead of starting and finishing a function call, and each waiting call holds memory until it returns. A loop repeats within a single call, with none of that per-call cost.

Q6What is the difference between direct and indirect recursion?▸

In direct recursion a function calls itself. In indirect recursion function A calls function B, which (directly or through other calls) calls A again. Both come back around to the original function on a smaller problem.

Q7In the Towers of Hanoi, what is the base case, and what does the recursive case do?▸

Base case: a single disk (count == 1), moved straight to the target. Recursive case: move the top count - 1 disks to the spare peg, move the largest disk to the target, then move the count - 1 disks from the spare onto the target.

Q8Trace sum_all([4, 2, 7]). How does the problem shrink, and what is the result?▸

It returns 4 + sum_all([2, 7]) → 4 + (2 + sum_all([7])) → 4 + (2 + (7 + sum_all([]))). The empty list hits the base case and returns 0, so the sum unwinds to 4 + 2 + 7 + 0 = 13. Each call removes the first element, shrinking the list toward empty.

Reference

Key terms

recursion
Solving a problem by having a function call itself on a smaller version of the same problem.
recursive function
A function that calls itself, directly or indirectly.
recursive call
The statement inside a recursive function where it calls itself.
base case
The condition simple enough to solve directly, without recursing; it stops the recursion.
recursive case
The condition that reduces the problem to a smaller one and calls the function again.
depth of recursion
The number of times a function calls itself before reaching the base case.
direct recursion
When a function calls itself.
indirect recursion
When function A calls function B, which in turn calls function A.
infinite recursion
Recursion with no reachable base case, which never stops on its own.
RecursionError
The exception Python raises when recursion exceeds the maximum allowed depth.
factorial
The product of all integers from 1 to n, written n!; 0! is defined as 1.
Fibonacci series
A sequence where each number is the sum of the two before it; it has two base cases.
greatest common divisor (GCD)
The largest integer that evenly divides two given integers.
Towers of Hanoi
A three-peg disk puzzle whose recursive solution moves the top n-1 disks aside, then the largest, then back.
call stack
The record of active, waiting function calls; each recursive call adds a frame until it returns.
