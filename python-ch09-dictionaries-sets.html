Dictionaries and Sets

Lists and tuples line data up in order and reach it by position. But a great deal of real data is naturally a lookup — a code that maps to a price, a name that maps to a score, a collection where the only thing that matters is whether something is in it. Python gives you two purpose-built containers for exactly that: the dictionary, which pairs keys with values, and the set, which holds unique items and answers membership and overlap questions fast.

Foundation

Dictionaries: pairing keys with values

A dictionary is an object that stores a collection of data as key–value pairs. Each element has a key and an associated value, and you reach a value by handing the dictionary its key — never by a numeric position. Because of that, a dictionary is often described as a mapping of keys to values.

Imagine the slots of a vending machine. Each slot has a short code, and each code holds one product. The code is how you ask for a product, so the code is the key and the product is the value:

create_dict.py
# key : value, separated by commas, wrapped in braces
slots = {"A1": "pretzels", "A2": "almonds", "B1": "raisins"}

print(slots["A2"])     # almonds   ← looked up by key, not by position
1Keys must be immutable▸

A key has to be an object that can't change — a string, a number, or a tuple, for example. Lists can't be keys, because a mutable key would break the dictionary's ability to find things. Values have no such rule: they can be any type at all.

2Keys are unique▸

Each key appears at most once. Assigning to a key that already exists doesn't add a second copy — it replaces the value that was there.

3Think lookup, not sequence▸

Modern Python keeps a dictionary's pairs in the order you inserted them, which is handy when you print one. But the whole point of a dictionary is fast access by key — so reach for it when you want to look something up, and don't write logic that depends on key positions the way you would with a list.

Empty to start

An empty dictionary is just {} (or dict()). You'll often create one empty and fill it as the program runs — you'll see that pattern below.

Reading data

Retrieving a value, and testing for a key

To read a value, subscript the dictionary with a key: dictionary[key]. If the key is present, you get its value back. If it isn't, Python raises a KeyError — and that's a crash you want to prevent rather than meet.

retrieve.py
slots = {"A1": "pretzels", "A2": "almonds", "B1": "raisins"}

print(slots["A1"])     # pretzels
print(slots["C9"])     # KeyError: 'C9'  ← that key isn't here

The fix is to ask first. The in and not in operators test whether a key exists, so you can guard the lookup:

guard.py
code_wanted = "C9"

if code_wanted in slots:
    print(slots[code_wanted])
else:
    print("That slot is empty.")     # runs — no crash
Habit worth forming

When a key might be missing, test with in before subscripting (or use the get method you'll meet shortly). It turns a hard crash into a graceful response.

What in checks

For a dictionary, in looks at the keys, not the values. "A1" in slots is True; "pretzels" in slots is False, because "pretzels" is a value, not a key.

Writing data

Adding and changing elements

Dictionaries are mutable, so you can grow and edit them after creation. One assignment statement does both jobs — dictionary[key] = value — and which job it does depends only on whether the key is already there.

add_change.py
slots = {"A1": "pretzels", "A2": "almonds"}

slots["B2"] = "cashews"     # B2 is new → a pair is ADDED
slots["A2"] = "walnuts"     # A2 exists  → its value is CHANGED

print(slots)
# {'A1': 'pretzels', 'A2': 'walnuts', 'B2': 'cashews'}
Same syntax, two outcomes

If the key is absent, the pair is inserted. If the key is present, its old value is overwritten — the dictionary never holds two pairs with the same key. That's worth remembering: an accidental reuse of a key silently replaces data rather than adding to it.

Filling an empty dictionary as you go

A common pattern is to start empty and add pairs while a loop runs — for example, tallying how many of each item a machine dispensed:

tally.py
sold = ["almonds", "raisins", "almonds", "cashews", "almonds"]

counts = {}                       # start empty
for item in sold:
    if item in counts:
        counts[item] = counts[item] + 1   # seen before → bump it
    else:
        counts[item] = 1                # first time → start at 1

print(counts)     # {'almonds': 3, 'raisins': 1, 'cashews': 1}
Writing data

Deleting elements

To remove a key–value pair, use the del statement with the key: del dictionary[key]. As with retrieval, asking to delete a key that isn't there raises a KeyError, so guard it the same way.

delete.py
slots = {"A1": "pretzels", "A2": "almonds", "B1": "raisins"}

del slots["B1"]            # raisins are discontinued

if "Z9" in slots:          # guard before deleting
    del slots["Z9"]
else:
    print("Nothing to remove at Z9.")

print(slots)     # {'A1': 'pretzels', 'A2': 'almonds'}
Crash to avoid

del slots["Z9"] with no guard raises KeyError: 'Z9' when that key is absent. Test with in first whenever the key might not be present.

Working through a dictionary

Size, mixed types, and iterating

How many pairs?

The built-in len function returns the number of key–value pairs:

size.py
slots = {"A1": "pretzels", "A2": "almonds"}
print(len(slots))     # 2

Keys and values can mix types

Keys must be immutable, but they don't all have to be the same immutable type — one dictionary can mix string keys, integer keys, and tuple keys. Values are even freer: any object at all, including lists and other dictionaries.

mixed.py
locker = {
    7: "helmet",                  # integer key, string value
    "spare": ["gloves", "map"],     # string key, list value
    (4, 2): "corner bin"            # tuple key (immutable, so allowed)
}
print(locker[7])         # helmet
print(locker[(4, 2)])    # corner bin

Looping over a dictionary

A for loop over a dictionary walks its keys, one per pass. With the key in hand, you can reach the value:

loop.py
slots = {"A1": "pretzels", "A2": "almonds", "B1": "raisins"}

for code in slots:
    print(code, "holds", slots[code])
# A1 holds pretzels
# A2 holds almonds
# B1 holds raisins
Looping gives keys

The loop variable receives each key, not each value. To get the value, subscript with the key — or use the items method (next section) to receive both at once.

The toolbox

Dictionary methods

Beyond subscripting, a dictionary carries a set of methods that make common jobs cleaner and safer. We'll work with a small inventory dictionary — item name to quantity on hand:

stock.py
stock = {"pretzels": 12, "almonds": 5, "raisins": 9}

get — lookup that can't crash

The get method returns the value for a key, but if the key is missing it returns a default instead of raising a KeyError. It's the safe alternative to []:

get.py
print(stock.get("almonds", 0))     # 5    ← key found
print(stock.get("cashews", 0))     # 0    ← key missing, default returned (no crash)

items — keys and values together

The items method returns the pairs as a sequence of tuples (a dictionary view). Loop over it with two variables and you receive the key and value at once — no subscripting needed:

items.py
for name, qty in stock.items():
    print(name, "=", qty)
# pretzels = 12
# almonds = 5
# raisins = 9

keys and values

keys returns just the keys; values returns just the values. Both give you something you can loop over or hand to list():

keys_values.py
print(list(stock.keys()))       # ['pretzels', 'almonds', 'raisins']
print(sum(stock.values()))      # 26   ← total items on hand

pop and popitem — remove and return

pop removes the pair for a given key and hands back its value (with a default if the key's missing). popitem removes and returns the last pair as a tuple — useful for draining a dictionary:

pop.py
left = stock.pop("almonds", 0)
print(left)        # 5    — and "almonds" is now gone from stock

pair = stock.popitem()
print(pair)        # ('raisins', 9)  — returned as a tuple, then removed

clear — empty it out

clear deletes every pair, leaving an empty dictionary:

clear.py
stock.clear()
print(stock)        # {}

A different container

Sets: a collection of unique items

A set stores a collection of data the way a mathematical set does. Three rules define it: every item is unique (no duplicates), the items are unordered (there's no first or last, and no indexing), and the items can be of different types. Sets shine when the question is "what's in here?" or "what do these two collections share?"

Creating a set

Build a set by passing an iterable — a list, tuple, or string — to the built-in set function. Any duplicates collapse to a single copy, which is exactly what makes sets useful for de-duplicating:

make_set.py
# from a list that has repeats
scans = [204, 118, 204, 350, 118, 204]
unique_ids = set(scans)
print(unique_ids)      # {350, 204, 118}  — duplicates gone, order not guaranteed

# an empty set MUST use set() — {} makes an empty DICTIONARY
fresh = set()
Two traps when creating sets

First, {} is an empty dictionary, not an empty set — use set() for an empty set. Second, set("crew") splits the string into its characters: {'c', 'r', 'e', 'w'}. To get a set of whole words, pass a list: set(["crew", "deck"]).

Working with a set

Building, changing, and scanning a set

Size, and adding items

Like everything else, len reports how many items a set holds. Sets are mutable: add puts in one item, and update merges in a whole group of items from an iterable.

grow.py
signed_up = {"welding", "avionics"}

signed_up.add("painting")              # one item
signed_up.update(["riveting", "avionics"])  # a group; "avionics" already in → ignored

print(len(signed_up))     # 4   — the duplicate didn't grow the set
Duplicates just vanish

Adding an item that's already present is harmless — the set simply stays as it was. You never have to check "is it already in here?" before adding; uniqueness is automatic.

Removing items

There are two single-item removers, and they differ only in how they handle a missing item: remove raises a KeyError if the item isn't there, while discard stays quiet. clear empties the whole set.

shrink.py
signed_up.discard("painting")    # removed
signed_up.discard("sky-diving")  # not there — discard shrugs, no error

signed_up.remove("sky-diving")   # KeyError! remove insists the item exists
Which remover?

Use discard when "remove it if it happens to be present" is what you mean — it's the safe choice. Reach for remove only when a missing item genuinely signals a bug you'd want to hear about.

Scanning a set

A for loop visits each item once (in no guaranteed order), and the in / not in operators test membership — the operation sets are fastest at:

scan.py
signed_up = {"welding", "avionics", "riveting"}

for course in signed_up:
    print(course)

print("avionics" in signed_up)       # True
print("plumbing" not in signed_up)  # True
Where sets earn their keep

Combining sets: union, intersection, difference

The real power of sets is comparing two of them. Each operation below has both a method form and an operator form — they do the same thing — and each returns a new set, leaving the originals untouched. Picture two course rosters: students enrolled in a Python class and students enrolled in a Java class.

rosters.py
python_roster = {"Maya", "Dev", "Ana", "Theo"}
java_roster   = {"Dev", "Ana", "Ravi"}

Union — everything in either set

union.py
everyone = python_roster.union(java_roster)    # or:  python_roster | java_roster
print(everyone)
# {'Maya', 'Dev', 'Ana', 'Theo', 'Ravi'}  — each name once

Intersection — only items in both

intersection.py
both_classes = python_roster.intersection(java_roster)  # or:  python_roster & java_roster
print(both_classes)
# {'Dev', 'Ana'}  — enrolled in both

Difference — in the first but not the second

difference.py
python_only = python_roster.difference(java_roster)   # or:  python_roster - java_roster
print(python_only)
# {'Maya', 'Theo'}  — in Python, not in Java

Symmetric difference — in one or the other, but not both

symmetric.py
just_one = python_roster.symmetric_difference(java_roster)  # or:  python_roster ^ java_roster
print(just_one)
# {'Maya', 'Theo', 'Ravi'}  — everyone NOT shared by both
Order matters for difference

Union, intersection, and symmetric difference give the same answer whichever set you start from. Difference does not: A - B (in A only) is different from B - A (in B only). Here java_roster - python_roster would be {'Ravi'}.

Comparing membership

Subsets and supersets

Two more comparisons ask about containment rather than overlap. Set A is a subset of set B if every item in A is also in B. Flip it around: B is then a superset of A — it contains all of A and possibly more.

subset.py
core_skills = {"riveting", "welding"}
all_skills  = {"riveting", "welding", "avionics", "painting"}

print(core_skills.issubset(all_skills))     # or: core_skills <= all_skills
# True   — every core skill is in the full list

print(all_skills.issuperset(core_skills))   # or: all_skills >= core_skills
# True   — the full list contains all the core skills
A practical read

Subset tests answer questions like "has this trainee completed all the required modules?" — required.issubset(completed) is True exactly when nothing required is missing.

Saving objects to a file

Serializing objects with pickle

You've built dictionaries and sets in memory — but memory disappears when the program ends. Serializing an object means converting it to a stream of bytes that can be written to a file and read back later, rebuilt into the same object. In Python, serializing is called pickling, and the pickle module does it for you.

Pickling: write an object out

The steps are always the same: import pickle, open a file for binary writing ("wb"), call pickle.dump(object, file), and close the file. You can dump several objects to one file before closing it.

save.py
import pickle

profile = {"call_sign": "BR-204", "hours": 312, "ratings": {"IFR", "night"}}

out_file = open("profile.dat", "wb")   # wb = write, binary
pickle.dump(profile, out_file)
out_file.close()

Unpickling: read it back

Reverse the process: open the file for binary reading ("rb"), call pickle.load(file), and close the file. What comes back is an equivalent object — here, a dictionary that still contains a set as one of its values:

restore.py
import pickle

in_file = open("profile.dat", "rb")    # rb = read, binary
profile = pickle.load(in_file)
in_file.close()

print(profile["call_sign"])    # BR-204
print(profile["ratings"])      # {'IFR', 'night'}  — the set came back intact
Two cautions with pickle

First, a pickle file is binary, not text — don't try to read it in a text editor, and always open with "wb"/"rb". Second, only unpickle files you trust: loading a pickle can execute arbitrary code, so never unpickle data from an unknown source.

Review

Check yourself

Predict each answer, then open the card. Even better, try it in the console above.

Q1Given slots = {"A1": "pretzels"}, why does slots["B1"] raise an error, and how do you avoid it?▸

"B1" isn't a key, so subscripting raises a KeyError. Avoid it by testing "B1" in slots first, or by using slots.get("B1", default), which returns the default instead of crashing.

Q2What does slots["A1"] = "walnuts" do when "A1" already exists?▸

It replaces the existing value — the dictionary now maps "A1" to "walnuts". The same statement would have added the pair if "A1" hadn't been there. Keys are unique, so there's never a second "A1".

Q3When you write for x in some_dict:, what does x receive on each pass?▸

Each key, not each value. To get the value, use some_dict[x] — or loop over some_dict.items() with two variables to receive the key and value together.

Q4What's the difference between a set's remove and discard methods?▸

Both remove the given item. If the item isn't in the set, remove raises a KeyError while discard does nothing. Use discard when a missing item is fine; use remove when its absence would indicate a bug.

Q5How is {} different from set()?▸

{} creates an empty dictionary, not a set. There's no brace shortcut for an empty set — you must write set(). (Once it has items, {1, 2, 3} is a set.)

Q6Given A = {1, 2, 3} and B = {3, 4}, what are A & B, A | B, and A - B?▸

A & B is {3} (in both), A | B is {1, 2, 3, 4} (in either), and A - B is {1, 2} (in A but not B). Note B - A would instead be {4}.

Q7What must be true for required.issubset(completed) to return True?▸

Every item in required must also appear in completed. In other words, nothing required is missing — completed may contain extras, which don't affect the result.

Q8You pickled a dictionary to a file. What mode do you open the file in to read it back, and what call rebuilds the object?▸

Open it in binary-read mode, "rb", then call pickle.load(file). (Writing used "wb" and pickle.dump(object, file).) Pickle files are binary, so text mode won't work.

Reference

Key terms

dictionary
An object that stores data as key–value pairs, accessed by key.
key
The lookup half of a pair; must be immutable and is unique within the dictionary.
value
The data half of a pair; may be any type of object.
mapping
Another name for the key-to-value association a dictionary provides.
key-value pair
A single element of a dictionary: one key and its associated value.
KeyError
Raised when you access or delete a key that isn't in the dictionary (or remove a missing set item).
in / not in
Operators that test whether a key (or set item) is present.
del statement
Removes a key–value pair: del d[key].
get method
Returns a key's value or a default if the key is absent; never raises KeyError.
items method
Returns the pairs as a sequence of (key, value) tuples.
keys / values methods
Return the dictionary's keys, or its values, as a sequence.
pop method
Removes a key's pair and returns its value (or a default).
popitem method
Removes and returns the last pair as a tuple.
clear method
Removes every element, leaving the dictionary or set empty.
dictionary view
The sequence-like object returned by items, keys, or values.
set
An unordered collection of unique items.
unique
Holding no duplicates; adding an item already present has no effect.
unordered
Having no positions or indexing; items aren't kept in a defined order.
set function
set() builds a set, optionally from an iterable; set() alone is the empty set.
add method
Adds one item to a set.
update method
Adds a group of items to a set from an iterable.
remove method
Removes a set item; raises KeyError if it's absent.
discard method
Removes a set item if present; does nothing if it's absent.
union
A set of all items in either set; a.union(b) or a | b.
intersection
A set of items in both sets; a.intersection(b) or a & b.
difference
Items in the first set but not the second; a.difference(b) or a - b.
symmetric difference
Items in exactly one of the two sets; a ^ b.
subset
Set A is a subset of B if every item of A is in B; a.issubset(b) or a <= b.
superset
Set A is a superset of B if A contains all of B; a.issuperset(b) or a >= b.
serialize
Convert an object to a stream of bytes that can be stored in a file.
pickling
Serializing an object with the pickle module's dump function.
unpickling
Rebuilding a pickled object from a file with pickle.load.
binary file
A file of raw bytes (opened with "wb"/"rb"), as pickle uses — not human-readable text.
