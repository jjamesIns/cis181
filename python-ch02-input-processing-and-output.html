Designing a Program

Good programs are designed before they are typed. Code is the last step, not the first.

Professional software is built in a repeating sequence called the program development cycle. Notice that writing code is only one stage of five — and it comes after design.

Design is the most important stage. Before writing anything, you work to fully understand the task: you talk with whoever wants the program built, ask questions about the details, and capture the answers as software requirements — the things the finished program must do. Then you break the task into a series of clear steps.

Algorithms, Pseudocode, and Flowcharts

That ordered set of steps is an algorithm: a set of well-defined, logical steps that must be taken to perform a task. Designers capture algorithms with two common tools before writing real code.

Pseudocode +

"Fake code" — an informal language with no syntax rules, never compiled or run. Because you ignore syntax, you can focus purely on the design, then translate it into any real language later.

Flowchart +

A diagram that graphically depicts the steps in a program. Ovals are terminal (start/end) symbols, parallelograms are input/output, rectangles are processing steps, and arrows show the flow.

Input, Processing, and Output

Most programs do three things, in this order.

A typical program performs a simple three-step process: it receives input, performs some processing on it, and produces output. Input is any data the program receives while it is running — perhaps typed at the keyboard. Processing is the work done on that data, often a calculation. Output is the result the program sends back.

A concrete example. A tip calculator reads the bill amount and tip percent (input), multiplies them and adds the result to the bill (processing), then shows the tip and grand total on screen (output). Almost everything you write this term fits this shape.

Displaying Output with the print Function

The print function is your program's voice.

A function is a piece of prewritten code that performs an operation. The print function displays output on the screen. The data you hand to a function is called an argument — for print, the argument is whatever you want displayed. Statements in a program execute in the order they appear, from top to bottom.

first_output.py
print("Welcome to the trail log.")
print("Let's record today's hike.")

Strings and String Literals

A string is a sequence of characters used as data. A string literal is a string written directly in your code, and it must be enclosed in quote marks — single (') or double ("). A literal enclosed in triple quotes (''' or """) may contain both kinds of quote and span multiple lines.

strings.py
print('Single quotes work.')
print("Double quotes work too.")
print("""Triple quotes can hold 'both' kinds
and even span more than one line.""")

Displaying Multiple Items

A single call to print can display several items at once. You separate them with commas when passing them as arguments; they appear in the order passed, and Python automatically puts a single space between them on screen.

multiple_items.py
miles = 5
print("Distance:", miles, "miles")
# Output:  Distance: 5 miles

Comments

Notes for humans, invisible to the interpreter.

Comments are notes of explanation within a program. The Python interpreter ignores them entirely — they exist for the people reading your code. A comment begins with a # character. An end-line comment appears at the end of a line of code and typically explains the purpose of that line.

comments.py
# Convert the hike duration from minutes to hours.
minutes = 150
hours = minutes / 60        # 60 minutes per hour
print("Duration in hours:", hours)
5

Variables

A variable is a name that points to a value stored in memory.

A variable is a name that represents a value stored in the computer's memory; you use it to access and manipulate that data. You create a variable with an assignment statement, whose general form is variable = expression. The equal sign is the assignment operator, and the variable receiving the value must always be on the left side.

variables.py
trail_name = "Sunrise Loop"
elevation_gain = 1240

print(trail_name, "climbs", elevation_gain, "feet.")

A variable can be passed as an argument to a function (without quote marks — quoting the name would turn it into a literal string instead). And you can only use a variable after a value has been assigned to it.

A Variable Is a Reference

A variable does not "contain" its value so much as reference it. Variables can reference different values while the program runs, and a variable that referenced one type can be reassigned to a completely different type. When a value is left with nothing referencing it, Python's garbage collection automatically reclaims that memory.

Variable Naming Rules

Python enforces a few rules, and convention adds one more:

Not a keyword +

A variable name cannot be one of Python's reserved key words (such as if or for).

No spaces +

Names cannot contain spaces. Use an underscore to join words: total_cost.

Valid first character +

The first character must be a letter or an underscore — never a digit.

Valid rest +

After the first character, you may use letters, digits, or underscores.

Case sensitive +

Total, total, and TOTAL are three different variables.

Reflect its use +

Convention, not a rule: choose a name that describes the value, so the code reads clearly.

Data Types: int, float, and str

A data type categorizes a value in memory. The three you meet first are int (whole numbers), float (real numbers with a decimal point), and str (strings). A numeric literal with no decimal point is treated as an int; with a decimal point it is a float. Some operations behave differently depending on the data type involved.

data_types.py
steps  = 8000          # int   — no decimal point
pace   = 9.5           # float — has a decimal point
runner = "Ada"         # str   — text in quotes

Reading Input from the Keyboard

The input function lets the user hand data to your program.

Most programs need to read input from the user. The built-in input function reads a line typed at the keyboard and always returns it as a string. The general format is variable = input(prompt), where the prompt is a string telling the user what to enter. Note that input does not automatically add a space after the prompt — include one yourself if you want the cursor to sit a space away.

greeting.py
name = input("Enter your name: ")
print("Good to see you,", name)

Reading Numbers

Because input always returns a string, you cannot do math on its result directly. Built-in functions convert between types: int(item) converts to an integer and float(item) converts to a floating-point number. Conversion only succeeds if the item is a valid number; otherwise Python raises an exception.

The usual pattern wraps the conversion around the input call — a nested function call, with the general form function1(function2(argument)). The value returned by the inner function is passed straight to the outer one.

read_numbers.py
age   = int(input("Enter your age: "))
price = float(input("Enter the price: "))

print("Next year you will be", age + 1)

Performing Calculations

Operators, operands, and the order Python applies them.

A math expression performs a calculation and produces a value. A math operator is the tool that performs it, and the operands are the values on either side of the operator (variables can be operands too). The resulting value is typically assigned to a variable.

The Math Operators

OperatorOperationExampleResult
+Addition12 + 517
-Subtraction12 - 57
*Multiplication12 * 560
/Floating-point division7 / 23.5
//Integer division7 // 23
**Exponent (power)3 ** 481
%Remainder (modulus)17 % 52

There are two kinds of division. The / operator performs floating-point division and always yields a float. The // operator performs integer division: positive results are truncated toward zero, and negative results round away from zero. The remainder operator % (also called modulus) returns what is left over after division — handy for converting units or testing whether a number is even or odd.

Operator Precedence and Parentheses

When an expression mixes operators, Python applies them in a fixed order of precedence. Operators of equal precedence are applied left to right.

precedence.py
print(2 + 3 * 4)        # 14  — * happens before +
print((2 + 3) * 4)      # 20  — parentheses force + first

Converting Math Formulas to Code

An operator is required for every mathematical operation — algebra's "implied" multiplication does not exist in code. When you translate a formula into a statement you often need to add multiplication operators and insert parentheses to preserve the intended order.

From algebra to Python. The formula y = 3x + 2 cannot be written y = 3x + 2. The multiplication must be explicit: y = 3 * x + 2.

Mixed-Type Expressions

The data type that results from a calculation depends on the operands. Two int values give an int; two float values give a float. When an int and a float are combined — a mixed-type expression — the int is temporarily converted to a float and the result is a float. Converting a float to an int truncates the fractional part.

mixed_types.py
print(5 + 2)        # 7    — int + int → int
print(5 + 2.0)      # 7.0  — int + float → float
print(int(7.9))     # 7    — fractional part truncated

Breaking Long Statements Across Lines

A very long statement is hard to read and can be cut off when printed. The line-continuation character — a backslash \ at the end of a line — lets you split one statement across several lines. Anything already inside parentheses can be broken across lines without the backslash.

long_lines.py
# Backslash continuation
total = base_fare * 2 + bag_fee * 3 + \
        seat_fee * 4 + snack_fee * 5

# Parentheses allow breaking with no backslash
total = (base_fare + bag_fee +
         seat_fee + snack_fee)

More About Data Output

Controlling exactly how output looks.

By default, the print function ends every line with an invisible newline character, and it separates multiple items with a single space. Two special arguments let you change that behavior.

ArgumentWhat it does
end='…'Replaces the newline at the end of the output with whatever delimiter you give (so the next print continues on the same line).
sep='…'Replaces the space between items with whatever delimiter you give.
end_and_sep.py
print("Loading", end="...")
print("done")            # Output:  Loading...done

print("2025", "11", "30", sep="-")   # Output:  2025-11-30

Escape Sequences and Concatenation

A special character inside a string literal is written with a leading backslash and acts as an embedded command. The two most common are \n (newline) and \t (horizontal tab). Separately, when the + operator is used on two strings it performs string concatenation — joining them — which is useful for breaking one long string literal into pieces.

escapes.py
print("Name:\tAda\nLevel:\t7")
# Output (tab-aligned, two lines):
#   Name:   Ada
#   Level:  7

greeting = "Welcome, " + "traveler!"   # concatenation

Formatting Numbers

The built-in format function formats how a number is displayed. It takes two arguments — the numeric value and a format specifier — and returns a string. The specifier can set precision and type, switch to scientific notation, add comma group separators, set a minimum field width, or show a value as a percentage. For an integer, use d as the type designator and do not specify precision.

formatting.py
print(format(12345.678, ",.2f"))  # 12,345.68
print(format(0.25, ".0%"))        # 25%
print(format(1234567, ",d"))       # 1,234,567

Named Constants

Give every meaningful number a name.

A magic number is an unexplained numeric value sitting in a program's code. Consider this line:

magic_number.py
total = subtotal * 0.0725

What is 0.0725? A sales-tax rate? A discount? Only whoever wrote the line knows for sure. Magic numbers cause three problems: their purpose is hard to determine; if the same value appears in many places, changing it means hunting down every copy; and you risk a typo every time you retype it (intending 0.0725 but typing 0.725 produces errors that are very hard to track down).

The fix is a named constant: a name that represents a value that does not change while the program runs. By convention its name is written in all capitals.

named_constant.py
SALES_TAX = 0.0725

total = subtotal * SALES_TAX
Why this is better. Named constants make code self-documenting (the name explains the value); easier to maintain (change the value in one place and it updates everywhere the constant is used); and less error-prone (you type the actual number only once).

Summary & Self-Check

The building blocks of every program you'll write from here on.

This chapter covered the program development cycle and design tools (algorithms, pseudocode, flowcharts); the input–processing–output model; displaying and formatting output with print and format; comments; variables, naming rules, reassignment, and the int/float/str data types; reading input and converting it with int() and float(); and performing calculations with operators, precedence, and named constants.

Check your understanding

Q1. Why is design considered the most important stage of the development cycle?
Because the rest of the work depends on it. A clear understanding of the task and a well-thought-out algorithm prevent expensive mistakes later; writing code before you understand the problem usually means rewriting it.
Q2. The input function returns the value "50", but you need to add 10 to it. What goes wrong, and how do you fix it?
input always returns a string, and you cannot do arithmetic on a string. Convert it first with int() (or float()): amount = int(input("...")) + 10.
Q3. What does 7 / 2 produce, and how does 7 // 2 differ?
7 / 2 is floating-point division and gives 3.5. 7 // 2 is integer division and gives 3 — the result is truncated toward zero rather than keeping the fraction.
Q4. Evaluate 2 + 3 * 4 and (2 + 3) * 4. Why are they different?
2 + 3 * 4 is 14, because * has higher precedence than + and runs first. (2 + 3) * 4 is 20, because parentheses force the addition to happen before the multiplication.
Q5. Give two reasons to replace a magic number with a named constant.
Any two of: it makes the code self-documenting (the name explains what the value means); it makes maintenance easier (change one line and every use updates); and it prevents typos from repeatedly retyping the number.
Q6. Which of these are valid variable names: 2nd_place, total_cost, final score, _count?
total_cost and _count are valid. 2nd_place is invalid (starts with a digit). final score is invalid (contains a space).
