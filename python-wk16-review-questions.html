Short Answer · 2 points each

  1. CLI vs. GUI.A command line interface takes typed commands at a prompt; a graphical user interface presents windows and visual components the user clicks. The CLI's advantage is speed and precision for an experienced user, and it is easy to automate; the GUI's advantage is discoverability — the available actions are visible, so the user does not have to memorize commands.
  2. Event-driven.The program builds its interface and then waits, responding to events — clicks, keystrokes — as the user generates them. The user determines the order of execution. The console programs earlier in the course ran top to bottom on a path the programmer fixed in advance; the program decided what came next, not the user.
  3. Widgets.A widget is a single visual component of a GUI. Any four: Label displays uneditable text; Button runs a callback when clicked; Entry accepts one line of typed input; Frame groups other widgets; Listbox offers a list of items to select from; Radiobutton and Checkbutton offer choices; Canvas is a surface for drawing.
  4. mainloop.It runs continuously, watching for events and dispatching them to the right callback. Without it the program would build its widgets and then reach the end of the code and exit — the window would flash by or never appear, and no click would ever be handled.
  5. pack and side.pack places a widget inside its container and makes it visible; a widget that is never packed does not appear. By default widgets stack vertically in the order packed. Passing side='left' arranges them horizontally instead — and 'right', 'top', and 'bottom' are also available.
  6. Frames.A Frame is a container, and each one arranges its own contents independently — so one window can mix layouts. A form with several rows, each holding a label and an entry side by side, is the standard example: without frames, every widget would join one single stack or one single row, and the rows could not be built.
  7. Callbacks.A callback (or event handler) is the function tkinter calls when an event occurs. command=self.handler passes the function object, to be called later when the click happens. command=self.handler() calls it immediately, while the window is still being built, and passes its return value — usually None — as the command, so the button does nothing when clicked.
  8. The input pattern.A Label prompts, an Entry receives the typed text, and a Button triggers the work. The callback calls the entry's get method, converts the string to the type it needs, performs the calculation, and displays the result — either in an info dialog or in a label wired to a StringVar.
  9. StringVar.A tkinter object that holds a string value. Passing it to a label as textvariable links the two, so calling the variable's set method updates the label's display automatically. This is how a program shows a result in the window itself rather than in a pop-up, without rebuilding the label.
  10. Radio vs. check buttons.Radio buttons are mutually exclusive — selecting one clears the others — because every button in the group shares one control variable, usually an IntVar, and each has a distinct value. Check buttons are independent, so each gets its own variable holding 1 or 0, and any number may be checked at once.
  11. Reading a Listbox.First call curselection(), which returns a tuple of indexes rather than the text. Then pass an index from that tuple to get() to retrieve the item. Before indexing, check that the tuple is not empty — nothing is selected when the window opens, and picked[0] on an empty tuple raises IndexError.

Exercise 1 · The Flight Time Calculator — 14 points

flight_calculator.py
import tkinter
import tkinter.messagebox

class FlightCalculator:
    def __init__(self):
        self.window = tkinter.Tk()
        self.row1 = tkinter.Frame(self.window)
        self.row2 = tkinter.Frame(self.window)
        self.row3 = tkinter.Frame(self.window)
        self.row4 = tkinter.Frame(self.window)

        tkinter.Label(self.row1, text='Distance (miles):').pack(side='left')
        self.distance = tkinter.Entry(self.row1, width=10)
        self.distance.pack(side='left')

        tkinter.Label(self.row2, text='Ground speed (mph):').pack(side='left')
        self.speed = tkinter.Entry(self.row2, width=10)
        self.speed.pack(side='left')

        self.result = tkinter.StringVar()
        tkinter.Label(self.row3, text='Flight time:').pack(side='left')
        tkinter.Label(self.row3, textvariable=self.result).pack(side='left')

        tkinter.Button(self.row4, text='Calculate',
                       command=self.calculate).pack(side='left')
        tkinter.Button(self.row4, text='Quit',
                       command=self.window.destroy).pack(side='left')

        self.row1.pack(); self.row2.pack()
        self.row3.pack(); self.row4.pack()
        tkinter.mainloop()

    def calculate(self):
        miles = float(self.distance.get())
        mph = float(self.speed.get())
        if mph == 0:                          # step 6 guard
            self.result.set('Speed cannot be 0')
        else:
            self.result.set(f'{miles / mph:.2f} hours')

app = FlightCalculator()
  1. Step 4 — why convert.get() always returns a string, whatever the user typed. Without float(), dividing two strings raises TypeError: unsupported operand type(s) for /: 'str' and 'str'. This is the same lesson as input() from Week 02 — the widget changed, the rule did not.
  2. Step 5 — distance 450, speed 180.The label reads 2.50 hours. With a speed of 0, the program raises ZeroDivisionError — and here is the part worth noting: the traceback appears in the console or IDLE window, not in the GUI. The window itself keeps running and simply appears to do nothing when clicked, which is why an unhandled exception in a GUI can be so confusing to diagnose.
  3. Step 7 — typing abc.ValueError: could not convert string to float: 'abc', raised by float(). Handle it by wrapping the conversions in try/except ValueError and setting the result label to a message such as "Enter numbers only" — the same detection-and-handling split from Week 06, with the label taking the place of a printed message.

Exercise 2 · The Parts Inspector — 14 points

parts_inspector.py — key portions
        # step 1 -- fill the Listbox from data
        self.parts_list = tkinter.Listbox(self.row1, height=4)
        for item in ['Bolt', 'Bracket', 'Gasket', 'Fairing']:
            self.parts_list.insert(tkinter.END, item)

        # step 2 -- ONE IntVar shared by both radio buttons
        self.status = tkinter.IntVar()
        self.status.set(1)
        tkinter.Radiobutton(self.row2, text='Pass',
                            variable=self.status, value=1).pack(side='left')
        tkinter.Radiobutton(self.row2, text='Fail',
                            variable=self.status, value=2).pack(side='left')

        # step 3 -- each check button gets its OWN IntVar
        self.reorder = tkinter.IntVar()
        self.urgent = tkinter.IntVar()
        tkinter.Checkbutton(self.row2, text='Reorder',
                            variable=self.reorder).pack(side='left')
        tkinter.Checkbutton(self.row2, text='Urgent',
                            variable=self.urgent).pack(side='left')

    def record(self):
        picked = self.parts_list.curselection()
        if len(picked) == 0:
            tkinter.messagebox.showinfo('Choose', 'Select a part first.')
            return
        name = self.parts_list.get(picked[0])
        self.canvas.delete('all')                      # clear before redrawing
        self.canvas.create_text(150, 20, text=name)     # small y = near the TOP
        color = 'green' if self.status.get() == 1 else 'red'
        self.canvas.create_rectangle(110, 40, 190, 70, fill=color)
        note = ''
        if self.reorder.get() == 1:
            note = note + 'Reorder '
        if self.urgent.get() == 1:
            note = note + 'Urgent'
        self.canvas.create_text(150, 95, text=note)     # larger y = BELOW
  1. Step 1 — why a loop.The loop separates the data from the code. Four insert calls hard-code the choices, so changing them means editing the program. A loop fills the widget from any list — including one read from a file or built at runtime — so the choices need not be known when the code is written. That is the Listbox's real advantage over radio buttons.
  2. Step 3 — one variable vs. several.Radio buttons share one IntVar, and a variable holds one value at a time — so selecting Fail sets it to 2, which automatically deselects Pass. The exclusivity is a consequence of the shared variable, not of anything about the widgets. Check buttons each own their own variable holding 1 or 0, so setting one has no effect on the other and any combination is possible.
  3. Step 5 — curselection.It returns a tuple of indexes, empty when nothing is selected. Without the guard, picked[0] raises IndexError: tuple index out of range — and since the list starts with nothing selected, that is the first thing a user can trigger. Note the return in the guard: it prevents the drawing code from running on a nonexistent selection.
  4. Step 7 — the coordinate system.Small y values are near the top and larger y values move down, so the y axis is inverted compared with a math graph, where y increases upward. The origin (0, 0) sits at the top-left corner rather than the center, and there are no negative coordinates on the visible canvas. This is why the title at y=20 appears above the notes at y=95.

Common errors to watch for. Forgetting self.canvas.delete('all'), so each click draws on top of the last and the canvas becomes an unreadable pile — a good demonstration of why the canvas holds items rather than pixels. Also watch for check buttons accidentally sharing one IntVar, which makes them behave like badly wired radio buttons.
