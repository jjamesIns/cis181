Introduction

A computer is a general-purpose machine: it has no fixed job until a program gives it one.

The single most important idea in this entire course is that computers can be programmed. The same laptop can edit a photo, route a delivery truck, or forecast tomorrow's weather — not because it was built three different ways, but because three different programs told it what to do.

A program is a set of instructions a computer follows to perform a task. Programs are also called software, and without software a computer is just an expensive paperweight: it cannot do anything on its own.

The person who designs, writes, and tests those instructions is a programmer — also called a software developer. That is the role you are training for. Throughout this book you will move from following instructions to writing them.

Think of it like a recipe. A recipe is a precise list of steps that turns raw ingredients into a finished dish. A program is a precise list of steps that turns input data into useful output. The cook is the CPU; the recipe card is the software; the chef who wrote the recipe is the programmer.
Program +

A set of instructions a computer follows to carry out a task. Commonly called software.

Programmer +

A person who designs, creates, and tests programs. Also known as a software developer.

General-purpose +

A computer is not locked to one task. Loading a different program gives it an entirely different job.

2

Hardware and Software

Hardware is the physical machine. Software is the instructions that bring it to life.

Hardware refers to the physical devices that make up a computer. A computer is not one single thing — it is a system of components that work together. The four major categories you will see again and again are the CPU, main memory, secondary storage, and input/output devices.

The CPU

The Central Processing Unit (CPU) is the part of the computer that actually runs programs — the single most important component, because nothing runs without it. Early CPUs were enormous, room-filling devices. Today a CPU fits on a tiny chip called a microprocessor, which is why a computer that once filled a building now fits in your pocket.

Main Memory

Main memory is where the computer holds a program while it is running, along with the data that program is working on. It is usually called RAM (Random Access Memory). The CPU can reach data in RAM very quickly. Crucially, RAM is volatile: it is temporary, and its contents vanish the moment the power goes off. That is why unsaved work disappears in a power outage.

Secondary Storage

Secondary storage holds data for long periods, even when the power is off. Programs normally live here and are copied into main memory only when they are needed. Common types:

TypeHow it stores data
Disk driveMagnetically encodes data onto a spinning circular platter; has moving parts.
Solid-state driveStores data in solid-state memory; faster than a disk drive and has no moving parts.
Flash memoryPortable solid-state storage (e.g., a USB stick) with no physical spinning disk.
Optical deviceEncodes data optically, read and written with a laser.

Input and Output Devices

Input is data the computer collects from people or other devices; an input device is the component that gathers it — a keyboard, mouse, touchscreen, microphone, or camera. Output is data the computer produces for people or other devices (text, images, audio, or a raw bit stream); an output device formats and presents it — a display or a printer.

A drive can be both. A storage drive acts as an input device when it loads a program into memory, and as an output device when the computer sends data to it to be saved. Whether something is "input" or "output" depends on which way the data is flowing.

Software: Two Big Families

Everything a computer does is controlled by software, and software falls into two broad categories.

Application software +

Programs that make the computer useful for everyday tasks — a spreadsheet, an email client, a video game, a web browser, a navigation app.

System software +

Programs that control and manage the computer's basic operations so applications can run on top of them.

Operating system +

The most fundamental piece of system software. It controls the hardware components and manages how programs share them.

Utility program +

System software that performs a specific task to enhance operation or safeguard data — a backup tool, an antivirus scanner, a disk cleaner.

Development tools +

System software used to create, modify, and test programs. Python's interpreter and IDLE belong here.

How Computers Store Data

Under the surface there is only one kind of data: patterns of on and off.

All data in a computer is stored as sequences of 0s and 1s. The smallest unit is the bit (short for binary digit) — a tiny electrical component that is either on (1) or off (0), like a light switch. Bits are grouped into bytes of eight bits each; one byte holds just enough to store a single letter or a small number. The on/off pattern of the eight bits in a byte is what represents the value stored there.

Storing Numbers in Binary

Computers count in the binary numbering system (base 2) rather than the decimal system (base 10) we use every day. Each position in a binary number has a place value that is a power of two. To find the value of a binary number, add up the place values wherever there is a 1.

A single byte can represent values from 0 (all eight bits off) to 255 (all eight bits on). To store a larger number, the computer simply uses several bytes together.

Storing Characters

Since memory can only hold numbers, characters must be turned into numbers too. Each character is assigned a numeric code, and that code is what gets stored in binary. For decades the dominant scheme was ASCII, which defines codes for only 128 characters — fine for English, but not nearly enough for the world's languages. The modern standard is Unicode, which is backward-compatible with ASCII but can represent characters from virtually every writing system.

Negative and Real Numbers

Plain binary handles whole, non-negative numbers, but computers also need negatives and decimals. They use special encoding schemes: two's complement for negative numbers, and floating-point notation for real numbers (values with a fractional part). You do not have to perform these encodings by hand — Python handles them — but it helps to know the machine has a defined way to represent each kind of value.

Every Other Kind of Data

Anything described as digital stores its data as binary numbers, and that includes far more than text:

Digital images +

An image is a grid of tiny dots called pixels. Each pixel's color is converted to a binary number, so the whole picture is just a long list of numbers.

Digital audio +

Sound is captured as many quick measurements called samples. Each sample is converted to a binary number, and playing them back in order recreates the sound.

The big idea +

Text, numbers, pictures, music, video — at the lowest level it is all binary. The meaning comes from how a program chooses to interpret those bits.

4

How a Program Works

A CPU only knows a handful of tiny operations. Everything else is built from millions of them.

A CPU is designed to perform only very simple operations on small pieces of data — reading a value, adding, subtracting, multiplying, dividing, and comparing. It understands instructions written in machine language: numeric codes drawn from the CPU's built-in instruction set. Each brand of CPU has its own instruction set, so machine language written for one family of chips will not run on a different one. Because each operation is so small, carrying out anything meaningful takes a great many of them.

The Fetch–Decode–Execute Cycle

Before a program can run, it is copied from secondary storage into main memory. The CPU then runs it by repeating one simple loop, billions of times per second, until the program ends.

From Machine Language to Assembly Language

Writing programs as raw binary machine language is brutally impractical for humans. Assembly language was the first improvement: it replaces binary codes with short words called mnemonics (like ADD or MOV) that are far easier to read and write. A program called an assembler then translates the assembly code back into the machine language the CPU actually executes.

High-Level Languages

Assembly is a low-level language — close in nature to machine language and tied to a specific CPU. A high-level language like Python lets you create powerful, complex programs without knowing how the CPU works internally or writing huge numbers of tiny instructions. The code reads much more like natural language and ordinary math, which makes it more intuitive to understand.

Key Words, Operators, and Syntax

Every high-level language is built from a few kinds of building blocks:

Key words +

Predefined words with a fixed, special meaning in the language (for example, Python's if, while, and def). You cannot use them for your own names.

Operators +

Symbols that perform operations on data — math operators such as +, -, *, and / being the most familiar.

Syntax +

The set of rules you must follow when writing a program. Break a rule and the language cannot understand your code.

Statement +

A single complete instruction written in the high-level language. A program is built from many statements.

Compilers and Interpreters

Because the CPU only understands machine language, high-level code has to be translated before it can run. There are two strategies for doing that:

CompilerInterpreter
What it doesTranslates the entire program into a separate machine-language program.Translates and executes the program one statement at a time.
OutputA standalone machine-language file you can run any time, even without the source.No separate file — results are produced as it runs.
Used byLanguages like C and C++.Python.
Python is interpreted. The statements you write are called source code. The Python interpreter reads your source code one statement at a time, translates it, and immediately carries it out. If a statement breaks the language's rules, you get a syntax error, and that statement cannot be translated or run.
5

Using Python

Two ways to talk to the interpreter: a quick conversation, or a saved script.

Before you can run any Python, the language has to be installed and configured on your machine. One of the things that gets installed is the Python interpreter — the program that reads and runs your code. Once it is in place, you can use it in two distinct modes.

Interactive Mode

In interactive mode, you type statements one at a time and the interpreter runs each one the instant you press Enter. You will see a prompt — >>> — which means the interpreter is waiting for a statement. After it runs your statement, the prompt reappears, ready for the next one. Type something incorrectly and it shows an error message right away. This makes interactive mode an excellent way to experiment with and learn new parts of the language.

interactive mode
>>> 15 + 27
42
>>> print("Systems online")
Systems online
>>> minutes = 90
>>> minutes / 60
1.5

Script Mode

Statements you type in interactive mode are not saved — close the session and they are gone. To keep a program, you use script mode: save a set of statements in a file whose name ends in .py. You then run the whole file from the operating system command line by typing python followed by the filename.

launch.py
# launch.py — a tiny script-mode program
pilot = "Ada"
fuel  = 120

print("Welcome aboard,", pilot)
print("Fuel remaining:", fuel, "units")

Run it from the command line:

terminal
$ python launch.py
Welcome aboard, Ada
Fuel remaining: 120 units
What a syntax error looks like. If you break the rules — here, a string is missing its closing quote — the interpreter refuses to run that line and reports the problem instead:
oops.py
print("Systems online)
SyntaxError: unterminated string literal

The IDLE Environment

When you install Python you also get IDLE (Integrated Development and Learning Environment): a single program that bundles together the tools to write, run, and test your code. It opens in interactive mode and includes a built-in text editor with features designed specifically to help you write Python — so you can move smoothly between trying ideas interactively and saving them as scripts.

Summary & Self-Check

The foundation every later chapter builds on.

In this chapter you learned the major hardware components of a computer; the two families of software; how all data is stored as bits and bytes in binary; the CPU's basic operations and machine language; the fetch–decode–execute cycle; how high-level languages are translated to machine code by compilers and interpreters; and how to run Python in interactive and script modes.

Check your understanding

Q1. Why is a computer called a "general-purpose" machine?
Because it has no built-in task of its own. Whatever job it does is determined by the program (software) currently loaded; change the program and the same hardware does something completely different.
Q2. Your unsaved work vanishes during a power cut. Which component explains this, and why?
Main memory (RAM). It is volatile — it only holds data while powered, so its contents are erased the instant the power is lost. Anything you want to keep must be written to secondary storage.
Q3. What is the largest value a single byte can hold, and why that number?
255. A byte has 8 bits; when all eight are 1, the place values 128+64+32+16+8+4+2+1 add up to 255. The smallest is 0, when all bits are off.
Q4. List the three steps of the cycle the CPU repeats, in order.
Fetch (read the next instruction from memory), Decode (work out which operation it represents), Execute (carry out the operation). Then it repeats.
Q5. How does an interpreter differ from a compiler, and which one does Python use?
A compiler translates the whole program into a separate machine-language file that can be run later. An interpreter translates and runs the program one statement at a time, producing no separate file. Python uses an interpreter.
Q6. When would you choose script mode over interactive mode?
Use script mode whenever you want to keep and reuse a program: statements typed in interactive mode are discarded when the session ends, while a saved .py file can be run again any time with python filename.
