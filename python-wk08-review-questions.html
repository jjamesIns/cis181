Short Answer · 2 points each

  1. Sequences.A sequence is an object that holds multiple items of data stored one after another in a definite order, so every item has a position. The two covered here are the list and the tuple; the essential difference is mutability — a list can be changed after creation, a tuple cannot.
  2. Indexes.An index is a number identifying an element's position. The first element's index is 0 and the last is len(list) - 1. Negative indexes count backward from the end: -1 is the last element, -2 the next-to-last, and so on.
  3. Mutable.A mutable sequence is one whose items can be changed after it is created. Assigning to a valid index replaces that element in place — trails[1] = "Gorge". Accept also append, remove, insert, sort, or reverse.
  4. Slices.A slice produces a new list containing copies of the elements from start up to but not including end. Omitting start makes Python use 0; omitting end makes it use len(list).
  5. remove vs. del.remove(item) searches by value and deletes the first occurrence, raising ValueError if the value isn't present. del list[i] deletes by position, raising IndexError if the index is invalid.
  6. In-place methods.append, insert, remove, sort, and reverse all modify the list in place and return None. So counts = counts.sort() sorts the list and then immediately overwrites the variable with None — the sorted data is lost and the next operation on counts fails.
  7. Copying.Assignment copies the reference, not the list, so both names end up referring to the one and only list object and a change through either is visible through both. Two ways to make a real copy: a full slice original[:], or the list(original) function. Accept also an empty list plus a loop that appends each element, or [] + original.
  8. Accumulator pattern.Create a variable set to 0 before the loop, then loop over the list adding each element to it. After the loop the variable holds the total; divide it by len(list) for the average.
  9. Comprehension form.[expression for variable in iterable]. The expression determines what goes into the new list; the variable is the target that receives one item per pass; the iterable is the source being walked. An optional if clause may follow to filter.
  10. When to use which.A comprehension is better when the body is a single expression — transforming or filtering every item — because it states the intent in one readable line. An ordinary loop is better when the body needs several statements, nested decisions, or line-by-line comments; if the comprehension can't be said aloud in one breath, write the loop.
  11. Why tuples.Any two of: processing a tuple is somewhat faster than an equivalent list; immutability guarantees the data cannot be altered by accident; and some Python operations require tuples specifically. Convert with list() and tuple().

  1. Step 2 — insert vs. remove.The number given to insert is a position — insert(0, 55) puts 55 at index 0 and shifts everything right. The number given to remove is a value — remove(610) searches for the element equal to 610 and deletes the first match, wherever it happens to be. Confusing the two is a common bug: remove(0) does not remove the first element.
  2. Step 4 — the sort bug.elevations displays as None. sort reorders the list in place and returns None, so assigning its result overwrites the variable and the entire list is lost. The correct usage is elevations.sort() as a statement on its own line. Accept mention of sorted() as the function that does return a new list.
  3. Step 6 — transform vs. filter.The feet comprehension transforms: the expression round(m * 3.28) changes each value, and every element of the source appears in the result. The high comprehension filters: its expression is just m, so nothing changes, and the if clause decides which items are kept. The expression does transforming; the if clause does filtering.
  4. Step 7 — comprehension vs. loop.The loop version is four lines: an empty list, a for, an if, and an append. The comprehension is one line that reads as a sentence. Either answer earns credit if justified — the comprehension for stating intent concisely, or the loop for being easier to extend and debug. What is graded is a reason, not a preference.

  1. Step 1 — the two lengths.len(scores) is 3, the number of rows — how many students. len(scores[0]) is 3, the number of columns in the first row — how many tests each student took. The outer length counts inner lists; the inner length counts values within one of them.
  2. Step 4 — why a comprehension fits a column.A column isn't stored anywhere — the data is grouped by row, so every row must be visited and one element pulled from each. That is exactly the shape of a comprehension: walk a sequence, take one value per item. [row[0] for row in scores] says "the first score from every student" in one readable line, where a loop would need an empty list and an append.
  3. Step 5 — aliasing.scores[0] becomes [0, 91, 77]. alias = scores copied the reference, not the data, so both names refer to the same list object and a change made through one is visible through the other. There was never a second list.
  4. Step 6 — why the slice copy still changed the original. scores[0] becomes [999, 91, 77] even though a copy was made. The slice did create a new outer list — but the elements it copied are themselves references to the three inner lists. So copy is a new list pointing at the very same rows. Changing copy[0][0] reaches through that shared reference into the original row. The slice copied the outer list only — this is called a shallow copy. Appending a whole new row to copy would not affect scores, because that changes the outer list; it is only edits reaching into a row that are shared.
  5. Step 7 — why a tuple.Any two of: immutability guarantees the coordinate cannot be altered by accident, which suits a fixed pair of values; processing a tuple is somewhat faster than an equivalent list; and some Python operations require tuples specifically. The exception raised is TypeError: 'tuple' object does not support item assignment.
