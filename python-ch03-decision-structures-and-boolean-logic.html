Foundation

Control structures

A control structure is the logical design that decides the order in which a set of statements runs. Every program you'll write is built from just three of them.

ASequence structure▸

Statements run in the exact order they appear, top to bottom, with no skipping and no repeating. Everything you wrote before this chapter was a single sequence.

BDecision structure▸

A specific action is performed only if a condition is true. The program tests something, then chooses a path. This is the subject of this chapter, and it's also called a selection structure.

CRepetition structure▸

A set of statements repeats while some condition holds. That's Chapter 4 — but decisions and repetition are close cousins, since both hinge on testing a condition.

Think of a fare gate at a train platform. The gate reads your card (sequence), then it makes a decision: if the balance covers the fare, the doors open; otherwise they stay shut. The reading always happens; the opening only happens when a condition is met. That conditional step is a decision structure.

Vocabulary

A single-path decision — "do this extra step only when the condition is true, otherwise just carry on" — is called a single alternative decision structure. It offers one alternative path of execution.

Single alternative

The if statement

The if statement creates a single alternative decision structure. It tests a condition; if the condition is true, an indented block of statements runs. If the condition is false, that block is skipped and the program moves on.

Picture a small greenhouse with an automatic fan. Every few minutes the controller reads the temperature. If it has climbed above the safe range, the fan switches on. If not, nothing happens and the next reading is taken.

greenhouse.py
temperature = 31

if temperature > 28:
    print("Greenhouse too warm — fan ON")

print("Reading logged.")

Anatomy of those lines:

  • The first line is the if clause: the keyword if, a condition that is either true or false, and a colon to end it.
  • The lines below it, indented, form the block that runs only when the condition is true.
  • The unindented print("Reading logged.") is not part of the if. It runs every time, because indentation — not braces — is what marks the block in Python.

With temperature set to 31, the condition 31 > 28 is true, so both lines print. Change it to 24 and the fan line is skipped entirely, while "Reading logged." still prints.

Don't do it

Forgetting the colon, or not indenting the block, are the two most common beginner errors here. if temperature > 28 with no colon raises a SyntaxError; a body that isn't indented raises an IndentationError.

Conditions

Boolean expressions & relational operators

The condition tested by an if statement is a Boolean expression — an expression that is either True or False. You build one with a relational operator, which tests whether a particular relationship holds between two values.

OperatorExpressionAsks the question…
>a > bIs a greater than b?
<a < bIs a less than b?
>=a >= bIs a greater than or equal to b?
<=a <= bIs a less than or equal to b?
==a == bIs a equal to b?
!=a != bIs a not equal to b?

Each of these evaluates to a real Boolean value. Try them on a count of players in a game:

>>> interactive session
>>> players = 4
>>> players == 4
True
>>> players != 5
True
>>> players > 4
False
>>> players >= 4
True

The >= and <= operators succeed when either relationship holds — players >= 4 is true because the player count is equal to 4, even though it isn't greater. Any of these operators can be used as the condition in a decision block.

The classic trap

= and == are different operators. A single = assigns a value (players = 4 puts 4 into the variable). A double == compares two values and produces True or False. Writing if players = 4: is a syntax error — Python is protecting you from a bug that plagues other languages.

Dual alternative

The if-else statement

Often a program needs to do one thing when a condition is true and a different thing when it's false. That's a dual alternative decision structure: two possible paths, and exactly one of them always runs.

A recreation center scanner reads a member ID at the door. A valid card carries a non-zero ID; an unregistered tap reads as zero. One path welcomes the member; the other sends them to the desk.

gate.py
member_id = 0

if member_id != 0:
    print("Welcome back — doors open.")
else:
    print("Not registered. Please see the front desk.")

The else clause has no condition of its own — it simply catches every case the if condition didn't. Notice the alignment: if and else start in the same column, and each block is indented the same amount beneath its clause. That alignment is what tells Python (and the reader) which statements belong to which branch.

Text comparisons

Comparing strings

Relational operators aren't just for numbers. Strings can be compared too — most commonly with == and != to check for an exact match, and also with <, >, <=, and >= to put them in order.

A simple command parser matches what the user typed against known commands:

parser.py
command = "start"

if command == "start":
    print("Engine running.")
elif command == "stop":
    print("Engine off.")
else:
    print("Unknown command.")
Case matters

String comparisons are case sensitive. "start" == "Start" is False, because a capital S and a lowercase s are different characters. If you want a tolerant match, convert first: command.lower() == "start".

How ordering works

When you use < or > on two strings, Python compares them character by character, using each character's underlying numeric code (its Unicode code point, which for ordinary letters matches the older ASCII values). It walks left to right and stops at the first position where the two strings differ — that comparison decides the whole result.

Compare "Cat" and "Car". The first two characters match exactly, so the decision comes down to the third:

Two more rules fall out of this character-by-character method:

  • If one string is a prefix of a longer one, the longer string is greater: "art" < "artist", because the first three characters tie and then "art" simply runs out.
  • Because uppercase letters have lower code points than lowercase letters ('A' is 65, 'a' is 97), an all-capitalized word sorts before a lowercase one: "Banana" < "apple" is True. That surprises people, so watch for it when sorting names.
Multiple conditions

Nested decisions & the if-elif-else statement

A decision structure can live inside another decision structure. This is called nesting, and it's how you express "if this is true, then also check that."

Suppose a ride has two requirements, and a rider must clear both: they must be at least 13 years old and at least 120 cm tall. Checking one inside the other looks like this:

ride_nested.py
age = 15
height_cm = 130

if age >= 13:
    if height_cm >= 120:
        print("You can ride.")
    else:
        print("Tall enough next year — not yet.")
else:
    print("Must be at least 13.")
Indentation is the structure

The inner else aligns with the inner if; the outer else aligns with the outer if. The amount of indentation is the only thing that tells Python which else pairs with which if. Line them up carefully and the logic reads itself.

A cleaner shape: if-elif-else

When you're really choosing one option out of several mutually exclusive ranges, deeply nested if-else blocks march further and further to the right and get hard to read. The if-elif-else statement flattens that ladder. Consider turning an air-quality index (AQI) reading into a plain-language advisory:

air_quality.py
aqi = 142

if aqi <= 50:
    print("Good")
elif aqi <= 100:
    print("Moderate")
elif aqi <= 150:
    print("Unhealthy for sensitive groups")
else:
    print("Unhealthy")

Python tests each condition from top to bottom and runs the block for the first one that's true — then skips the rest of the ladder entirely. With aqi at 142, the first two tests fail, the third (aqi <= 150) is true, so it prints "Unhealthy for sensitive groups" and never reaches the else. The order matters: because each branch already ruled out the smaller ranges above it, you only need the upper bound on each rung.

Good to know

The if-elif-else statement is never strictly required — anything it does can be written with nested if-else blocks. But the ladder keeps the clauses aligned in one column instead of drifting rightward, so the logic is far easier to follow. Use it whenever you're picking one option from several.

Compound conditions

Logical operators

Logical operators let you build compound Boolean expressions out of simpler ones. Python has three: and, or, and not.

andTrue only when both are true▸

and is a binary operator: it joins two Boolean expressions and the result is true only when both sides are true. It's perfect for collapsing the nested ride check from the previous section into one line.

orTrue when either is true▸

or is also binary: the result is true when at least one side is true, and false only when both are false.

notReverses a Boolean value▸

not is a unary operator — it takes a single Boolean expression and flips its truth value. not True is False, and not False is True.

With and, the two-part ride requirement becomes a single, readable condition — no nesting required:

ride_combined.py
if age >= 13 and height_cm >= 120:
    print("You can ride.")
else:
    print("Sorry, you don't meet the requirements.")

or works the same way when only one of several conditions needs to hold. A store offers free shipping when the order reaches a threshold or the shopper is a member:

shipping.py
if order_total >= 50 or is_member:
    print("Free shipping!")

And not reads cleanly when you want to act on the absence of something. Instead of comparing to False, flip the value directly:

access.py
if not logged_in:
    print("Please sign in first.")
Use parentheses for clarity

When you mix operators, parentheses make your intent unmistakable — and sometimes change the meaning. not (a == b) reverses the comparison, while (not a) == b means something different. When in doubt, add the parentheses; they cost nothing and prevent bugs.

Short-circuit evaluation

Python is efficient about compound expressions: it stops as soon as the answer is certain. This is called short-circuit evaluation, and both and and or do it.

  • For or: if the left operand is true, the whole expression is already true, so the right operand is never evaluated.
  • For and: if the left operand is false, the whole expression is already false, so the right operand is never evaluated.

This isn't just a speed trick — it lets the left side guard the right side. Here the left test prevents a division by zero from ever running:

guard.py
if count != 0 and total / count > 10:
    print("Average is above ten.")

If count is 0, the left side count != 0 is false, so Python short-circuits and never evaluates total / count — sidestepping the ZeroDivisionError that would otherwise crash the program.

A common pattern

Checking numeric ranges

A frequent job for logical operators is testing whether a number falls inside or outside a range of values. The pattern is worth memorizing.

Inside a range → use and

A thermostat keeps a room in a comfort band between 18°C and 24°C. The reading is comfortable only when it clears the lower bound and stays under the upper bound:

comfort.py
if temp >= 18 and temp <= 24:
    print("Comfortable.")
Python shortcut

Python lets you write that range check the way it looks in math: if 18 <= temp <= 24: means exactly the same thing as the and version above. Most other languages don't allow this, so it's a small Python perk worth knowing — though the explicit and form is just as correct.

Outside a range → use or

To flag a reading that has drifted out of the comfort band — too cold or too hot — switch to or and reverse the comparisons:

alert.py
if temp < 18 or temp > 24:
    print("Out of comfort range — adjusting.")
Watch the operator

It's tempting to write an "outside" test with and: temp < 18 and temp > 24. That can never be true — no single number is below 18 and above 24 at the same time. "Outside a range" always wants or; "inside a range" always wants and.

Storing a yes/no

Boolean variables

A Boolean variable holds one of just two values: True or False. Its type is bool, and it lets you remember the answer to a yes/no question and act on it later.

Boolean variables are most often used as flags. A flag is a variable that signals whether some condition has occurred: set it to False to mean "hasn't happened yet," and switch it to True the moment it does. Searching a list of stock codes for a target is the classic case:

stock_check.py
inventory = ["A21", "B07", "C44", "D90"]
target = "C44"

found = False          # flag starts off: not found yet

for code in inventory:
    if code == target:
        found = True      # raise the flag

if found:
    print("In stock.")
else:
    print("Not found.")

Two details make the flag pattern read well. First, the variable name describes the condition it tracks (found), so the later test if found: reads almost like a sentence — there's no need to write if found == True:, because found is already a Boolean. Second, the flag is initialized before the loop and only ever raised inside it, so after the loop ends it faithfully reports whether the target was seen anywhere along the way.

Reads like English

Because a Boolean variable already is True or False, use it bare in a condition: prefer if found: over if found == True:, and if not found: over if found == False:. Shorter, and it matches how you'd say it out loud.

Review

Check yourself

Predict the answer, then open each card to confirm. Better still, paste the code into the console above and run it.

Q1What does 15 != 15 evaluate to?▸

False. The values are equal, so "not equal" is false.

Q2Is "apple" < "apricot" true or false?▸

True. The first two characters (a, p) match; at the third, 'p' (112) is less than 'r' (114), so "apple" comes first.

Q3Which prints? if 5 > 3 or 9 < 1:▸

The body runs. or is true when either side is true, and 5 > 3 is true — so the second test isn't even evaluated (short-circuit).

Q4Rewrite "x is between 1 and 10 inclusive" as a condition.▸

x >= 1 and x <= 10 — or, Python-style, 1 <= x <= 10. Inside a range always uses and.

Q5Why is if found == True: redundant?▸

Because found is already a Boolean — it's True or False on its own. Just write if found:.

Q6In an if-elif-else ladder, how many blocks run?▸

Exactly one — the block for the first condition that's true (or the else if none are). Python skips the rest of the ladder the moment a match is found.

Key terms

control structure
A logical design that controls the order in which statements run.
sequence structure
Statements that execute in the order they appear.
decision (selection) structure
A structure in which an action runs only if a condition is true.
single alternative
A decision with one optional path — the plain if statement.
dual alternative
A decision with two paths — the if-else statement.
Boolean expression
An expression that evaluates to True or False.
relational operator
An operator that tests a relationship between two values: > < >= <= == !=.
if-elif-else
A flattened decision that picks one option from several mutually exclusive conditions.
logical operator
and, or, and not — used to build compound Boolean expressions.
short-circuit evaluation
Deciding a compound expression's value after evaluating only one operand.
Boolean variable
A variable of type bool holding True or False.
flag
