True or False

10 × 1 pt = 10
  1. T / F

    Indexing, slicing, the in operator, and len all work on strings just as they do on lists.

  2. T / F

    A string can be changed in place by assigning to one of its indexes.

  3. T / F

    Concatenating onto a string variable with += edits the original string object.

  4. T / F

    A slice of a string produces a new string.

  5. T / F

    The expression "12.5".isdigit() returns True.

  6. T / F

    The expression "Bay 12".isalnum() returns False.

  7. T / F

    The upper method changes the string it is called on.

  8. T / F

    String comparisons with == are case-sensitive.

  9. T / F

    The find method raises an exception when the substring is missing.

  10. T / F

    The split method returns a list.

Short Answer · 2 points each

  1. Strings as sequences.A string is a sequence of characters stored in a definite order, so each character has a numbered position. Because of that, the operations that work on lists work on strings too: indexing, slicing, the in operator, len, iteration with a for loop, and the repetition operator. Any three.
  2. Two ways to reach characters.Iterate with a for loop, which hands you one character per pass — best when every character must be examined, such as counting occurrences. Or index directly with word[i], which returns a one-character string — best when you want one specific position, such as the first or last character.
  3. Immutability.Once created, a string cannot be changed. greeting += " there" does not edit the original: Python builds a brand-new string containing the combined text and rebinds the variable to it. The original object is left untouched and, with nothing referencing it, is simply discarded.
  4. Why tag[0] = "H" fails.Assigning to an index would change the string in place, which immutability forbids — it raises TypeError: 'str' object does not support item assignment. Instead you build a new string, for example by concatenating "H" + tag[1:] or by calling a method that returns a modified copy.
  5. Slices.A slice returns a new string containing copies of the characters from start up to but not including end — a substring. Omitting start makes Python use 0; omitting end makes it use len(string).
  6. in versus find.in returns a Boolean — use it when a yes-or-no answer is all you need. find returns the index where the substring begins, so use it when the position matters. The catch with find is that a missing substring returns -1 rather than raising an exception, so the result must be checked.
  7. Testing methods.They all examine the string for some characteristic and return a Boolean rather than changing anything. They tidy validation because the check can happen before a risky operation — testing user_text.isdigit() first lets the program re-prompt rather than letting int() raise an exception.
  8. What isdigit() rejects.Any two of: a decimal number such as "12.5", because the period is not a digit; a negative number such as "-7", because the minus sign is not a digit; a value with surrounding spaces such as " 42"; and the empty string, which returns False because the method requires at least one character. This is why isdigit alone is not sufficient validation for a float.
  9. Why methods return copies.Because strings are immutable, no method can alter the original — so each returns a brand-new string with the change applied. That means you must use the return value: assign it to a variable or pass it onward. Calling the method as a bare statement accomplishes nothing.
  10. Case-insensitive comparison.Convert both sides to the same case first — answer.lower() == "yes". Without it the comparison fails because == is case-sensitive: "YES" and "yes" are different strings, since uppercase and lowercase letters are different characters.
  11. split.With no argument it breaks the string at whitespace, giving the individual words. With a separator argument it breaks at that character instead, such as a comma. Either way it returns a list of strings.

Exercise 1 · The Password Strength Checker — 14 points

interactive mode
>>> def analyze(password):
...     upper = lower = digit = 0
...     for ch in password:
...         if ch.isupper():
...             upper += 1
...         elif ch.islower():
...             lower += 1
...         elif ch.isdigit():
...             digit += 1
...     return upper, lower, digit
...
>>> analyze("Falcon2026")
(1, 5, 4)
>>> def is_strong(password):
...     u, l, d = analyze(password)
...     return len(password) >= 8 and u > 0 and l > 0 and d > 0
...
>>> for pw in ["Falcon2026", "hikeon", "PASSWORD1", "Ab3"]:

  1. Step 2 — why elif.The three conditions are mutually exclusive: a character cannot be both an uppercase letter and a digit. Using elif stops testing as soon as one matches, which is both faster and clearer about the intent. Three separate if statements would produce the same counts here, but they invite a bug the moment a condition overlaps — and they hide the fact that the categories are exclusive. Accept either justification.
  2. Step 4 — three different failures.hikeon is too short and has no uppercase and no digits — it fails on length first. PASSWORD1 is long enough and has uppercase and a digit, but has no lowercase letters. Ab3 has one of each kind but is only 3 characters, so it fails the length test alone. Full credit requires naming the distinct reason for each, not just "not strong."
  3. Step 6 — two ways to reject a space.Any two of: test the whole string with " " in password; test each character in the loop with ch.isspace(); or compare password to password.strip() — though that catches only leading and trailing spaces, not interior ones, which is worth noting.
  4. Step 7 — the discarded return value.Nothing would happen. password.strip() builds a stripped copy and returns it, but as a bare statement the copy is immediately discarded and password is unchanged — because strings are immutable, no method can alter it in place. To keep the result you must assign it: password = password.strip().

Exercise 2 · The Trail Record Parser — 14 points

interactive mode
>>> line = "  ORD-48715 , Falcon Ridge , 1520 , OPEN  "
>>> parts = line.split(",")
>>> parts
['  ORD-48715 ', ' Falcon Ridge ', ' 1520 ', ' OPEN  ']
>>> clean = [p.strip() for p in parts]
>>> clean
['ORD-48715', 'Falcon Ridge', '1520', 'OPEN']
>>> code, name, elev, status = clean
>>> code[:3], code[4:], code[4:].isdigit()
('ORD', '48715', True)
>>> code.find("-")
3
>>> int(elev) + 100
1620
>>> status.lower() == "open"
True
>>> renamed = name.replace("Ridge", "Peak")
>>> renamed, name
('Falcon Peak', 'Falcon Ridge')
  1. Step 2 — the problem with parts.Every piece still carries stray spaces — ' ORD-48715 ', ' Falcon Ridge ', and so on. split(",") breaks the string only at the commas and keeps everything else exactly as it was, including the spaces that surrounded each comma and the leading and trailing spaces of the whole line.
  2. Step 3 — why a comprehension.parts is a list, and strip() is a string method — calling it on the list would raise an AttributeError. The stripping has to happen to each element individually, which means visiting every item: a comprehension or a loop. [p.strip() for p in parts] does it in one line.
  3. Step 5 — the fragile slice.code[4:] assumes the prefix is exactly three characters plus a dash. A four-letter prefix such as "BOLT-48715" would make code[4:] return "48715" only by luck of that example — with "BOLT-1234" it would still start one character late or early depending on the prefix length. The reliable approach is to locate the separator first: pos = code.find("-"), then slice code[:pos] and code[pos+1:], so the code adapts to any prefix length.
  4. Step 6 — why convert.elev is the string '1520', not the number 1520 — split always produces strings, no matter what the text looks like. Arithmetic on a string either fails with a TypeError or, with + and another string, silently concatenates. int() is required before any calculation.
  5. Step 7 — what displaying both proves.renamed holds 'Falcon Peak' while name still holds 'Falcon Ridge'. That proves string methods do not modify the string they are called on — they return a brand-new string, exactly as immutability requires. The original survives untouched unless you deliberately reassign it.
PointsEarned for
3Steps 1–2: correct split on commas, with the untrimmed result displayed.
3Steps 3–4: comprehension strips every piece, four values unpacked correctly.
2Step 3 explanation — strip is a string method, so each element must be visited.
2Step 5: slices and find correct, with a working fix for the fragile slice.
2Step 6: conversion performed, and explained as split always yielding strings.
2Step 7: case-insensitive match, replace copy, and immutability correctly concluded.
Common error to watch for. Writing parts.strip() in step 3 and getting AttributeError: 'list' object has no attribute 'strip'. It is worth surfacing in class — it is the moment students see that methods belong to a type, not to data in general.
